**Omega-Fire** — это TUI-приложение (Terminal User Interface) на Python, построенное на [Textual](https://github.com/Textualize/textual). Оно предоставляет из терминала единый интерфейс для администрирования межсетевых экранов Linux, Fail2Ban, забаненных адресов, сетевых правил, журналов и системной статистики.

Интерфейс Textual — режим работы по умолчанию: навигация по меню, проверенным формам (все обязательные поля проверяются перед продолжением) и выделенным экранам, с темами, контекстной справкой и клавиатурными сочетаниями, общими для всей линейки OMEGA (omega-check, omega-deep, omega-stress...). Старый интерфейс [Rich](https://github.com/Textualize/rich), последовательный и управляемый вводом номеров, остаётся доступным через `--legacy-cli` (см. [Запуск](#запуск)).
Превью: [Screenshots](https://kraynux.snake-mackarel.ts.net/omega-fire/screenshots/index-2.html)


Проект спроектирован по принципам **Clean Architecture**, с чётким разделением между бизнес-доменом, оркестрацией, инфраструктурой и пользовательским интерфейсом.

## Обзор

Omega-Fire выступает как **локальный пульт управления** сетевой безопасностью. Он автоматически определяет присутствующие на машине компоненты и адаптирует меню под реально доступные возможности.

### Цели

- Объединить nftables, iptables, ip6tables и Fail2Ban в едином связном интерфейсе.
- Упростить наблюдение и управление соединениями, банами и системными событиями.
- Централизовать экспорт, резервные копии, аудит и историю операций.
- Сохранить тестируемую и расширяемую архитектуру.
- Работать в деградированном режиме при отсутствии опционального компонента.

### Что делает Omega-Fire

- Определяет доступные бэкенды, службы, ядро и инструменты.
- Администрирует nftables, iptables и ip6tables, когда эти компоненты присутствуют.
- Управляет забаненными IP, по одному или пакетами, с импортом, экспортом, синхронизацией и полной очисткой.
- Создаёт, отображает и удаляет расширенные правила.
- Применяет предустановленные политики с предварительным автоматическим резервным копированием.
- Администрирует jail'ы Fail2Ban и их баны.
- Анализирует логи в реальном времени или в виде статистики.
- Предлагает наблюдение в виде мониторинга.
- Использует conntrack для отображения активных соединений, если он доступен.
- Формирует экспорты в JSON, TXT и HTML.
- Сохраняет и восстанавливает полное состояние в архивах `.tar.gz`.
- Журналирует операции в прикладном журнале и структурированном JSON-аудите.
- Отслеживает обнаруженные службы и приложения: systemd, runit, OpenRC, Docker, серверы, VNC и т. д.

### Чего проект не делает

- Не заменяет nftables, iptables или Fail2Ban.
- Не является автономным межсетевым экраном, независимым от системы.
- Не предоставляет многопользовательскую аутентификацию.
- Не открывает сетевой API в обычном режиме работы.
- Не является веб-дашбордом.
- Не защищает напрямую удалённую машину с другой машины.
- По умолчанию не устанавливает ни одного файла за пределами собственной папки.
- Не гарантирует доступность всех бэкендов на всех дистрибутивах.

## Возможности

### 1. Возможности системы и диагностика

- Отображение реестра обнаруженных возможностей.
- Подробный просмотр возможности по идентификатору.
- Ручное пересканирование системы после установки компонента.
- Просмотр недавних диагностик.
- Просмотр и поиск в прикладном журнале.
- Экспорт состояния и диагностики в JSON, TXT или HTML.
- Категория **Пакет omega**: omega-serv (обнаруженные и работающие экземпляры), omega-waf (включено расширение `magnet`) и omega-jail (установленные jail), отображаются в реестре, на дашборде и в отчётах.

### 2. Единое управление IP

Единый чёрный список позволяет работать с nftables и iptables с одного экрана.

- Бан одного IP или списка IP.
- Индивидуальный или пакетный разбан.
- Прямой ввод или импорт из файла.
- Список по бэкенду или единое представление.
- Синхронизация между бэкендами NFTables/IPTables.
- Экспорт и повторный импорт списков.
- Полная очистка одного или нескольких бэкендов.
- Поддержка IPv4 и IPv6.
- Управление файлами блок-листов (`var/blocklist/`) и их закладками прямо с выделенного экрана.

### 3. Управление правилами и политиками

- Пошаговый мастер создания расширенного правила.
- Список системных правил и правил, созданных Omega-Fire.
- Удаление правила по выбору.
- Автоматическая очистка неактивных правил в эталонной базе.
- Очистка и повторная синхронизация базы с реальным файрволом, с предпросмотром и предварительным резервным копированием, без какого-либо изменения самого файрвола.
- Правила других инструментов (UFW, Tailscale, Docker…) определяются по происхождению: показываются для сведения и никогда не удаляются из Omega-Fire.
- Защита перед применением политики или очисткой iptables, когда там есть правила других инструментов: применить везде, только в nftables или отменить — последствия подробно описаны в справке.
- Применение предустановленных политик.
- Автоматическое резервное копирование перед применением политики.
- Настройка, сохранение и восстановление политики.
- Отображение активной политики в меню статуса и на дашборде.
- Обозначение изменённых профилей в виде `Профиль + CUSTOM`.
- Управление таблицами (меню 3.5): диагностика только для чтения по каждому бэкенду (наличие таблицы, политики input/output/forward, число правил) с объяснением различающихся между бэкендами политик (реальный эффект, причина и решение).
- Инициализация таблицы nftables при первом использовании — без перезаписи уже настроенной цепочки.
- Сброс политик цепочек на ACCEPT для одного backend'а — для исправления устаревшей ограничительной политики, оставшейся от предыдущего профиля.
- Очистка выбранного backend'а или синхронная очистка всех обнаруженных backend'ов одним действием.
- Полное удаление таблицы nftables (расширенное действие, затрагивающее не только правила).

### 4. Управление Fail2Ban

- Подробное состояние jail'ов и их параметров.
- Количество забаненных IP и информация о лимитах.
- Поиск IP в jail'ах.
- Индивидуальный или множественный бан/разбан.
- Перенос IP между jail'ами, бэкендами и файлами.
- Управляемое создание пользовательского jail.
- Предустановленные шаблоны jail'ов, редактируемые и удаляемые.
- Происхождение каждого jail: Omega-Fire, omega-jail, основная конфигурация fail2ban или другой файл.
- Надёжное удаление jail независимо от имени его файла: предупреждение для jail, установленного omega-jail, объяснённый отказ для jail из `jail.local` или из общего файла, стандартные фильтры fail2ban никогда не удаляются.
- Очистка одного jail или общая очистка всех.
- Экспорт в JSON, TXT или HTML.
- Проверка и аудит конфигурации.
- Управление службой: статус, запуск, остановка, перезапуск, включение и отключение автозапуска; после запуска или остановки реестр возможностей и дашборд обновляются.

### 5. Логи и обслуживание

- **Библиотека логов** (5.1): автоматический импорт логов обнаруженных экземпляров omega-serv, включая логи omega-waf, ручное закрепление пути и получение удалённого лога по SSH (ключ или агент, никогда не пароль).
- **Избранное** (5.2): объединять логи из Библиотеки, сохранять их под именем с выбранным просмотрщиком и запускать напрямую.
- **Просмотр логов** (5.3): один лог без настройки, в выбранном просмотрщике — Простой (дашборд в реальном времени), Классический (последние строки, затем слежение в реальном времени) или `lnav`.
- Интеграция `lnav`: несколько логов объединяются в одно хронологическое представление, инкапсулированное в header/footer Omega-Fire (см. [Навигация](#навигация)).
- Анализ самых частых IP с помощью Top N, с экспортом для повторной загрузки в адресную очистку.
- Адресная очистка одного или нескольких IP в файлах LOG или TXT, введённых вручную или отмеченных из экспорта.
- Закреплённые файлы с **пресетами для отметки**: предлагаются только привычные пути, реально существующие на машине.
- Немедленная или автоматизированная ротация и резервное копирование.
- Восстановление резервной копии.
- Очистка по возрасту, квоте, типу или ручному выбору.
- Расширенная очистка по папке или окружению.
- Статистика за 24 часа, 7 дней или 30 дней.
- Анализ событий, перемещений, квот и IP, присутствующих в jail'ах.

### 6. Экспорт и отчёты

Доступные форматы:

- **JSON** — структурированные и повторно используемые данные.
- **TXT** — необработанный формат или формат для инъекции.
- **HTML** — читаемый и визуальный отчёт.

Доступные отчёты:

- Полный чёрный список.
- Структурированный набор правил.
- Правила по происхождению: системные, Omega-Fire или активные.
- Полный отчёт аудита.
- Статистика Fail2Ban.
- Состояние и диагностика системы.
- Статистические отчёты за 7 или 30 дней.
- Рейтинг Top N IP-адресов.
- Руководство по справке и FAQ.

**Просмотр всех экспортов** (6.5): все экспортированные файлы в одном месте, с типом, датой и размером; HTML-отчёт открывается в веб-браузере пользователя по умолчанию, JSON или TXT читается в Omega-Fire, без терминала и файлового менеджера.

Темы HTML:

- `omega-base` — ночной синий и циан, тема по умолчанию.
- `omega-burn` — красно-оранжевые угли.
- `omega-neon` — киберпанк циан и маджента.
- `light-basic` — светлая и строгая.
- `light-alt` — кремовая бумага и лесной зелёный.

Язык экспорта: настраивается отдельно в настройках (по умолчанию « Как интерфейс »), чтобы передать отчёт на языке читателя, не меняя язык интерфейса.

### 7. Система и хранение данных

- Резервное копирование полного состояния: правила, баны nftables, баны iptables и Fail2Ban.
- Создание архивов `.tar.gz` с временной меткой.
- Список и восстановление снимков: возвращаются только правила Omega-Fire, которые можно воссоздать в точности; правила других инструментов никогда не затрагиваются.
- История действий.
- Фильтрация и очистка истории.
- Перезагрузка конфигурации и пересканирование без перезапуска.

### 8. Мониторинг и статистика

- Дашборд в реальном времени с периодическим обновлением (каждые 2 секунды), без блокировки интерфейса во время сбора данных.
- Отображение активной политики.
- Активные соединения через conntrack.
- Трафик, события, статистика и серверные логи.
- Сводные отчёты за 7 и 30 дней.
- Экспорт снапшотов и отчётов в HTML.

### 9. Настройки

- Выбор активной темы из десяти тем `omega-*`, общих для всей линейки (см. [Темы и терминалы](#темы-и-терминалы)), сохраняется между запусками.
- Ручное переопределение профиля рендеринга (авто, полный, стандартный, уменьшенный или только моно), применяется при следующем запуске.
- Язык интерфейса из 17 языков (см. [Языки интерфейса](#языки-интерфейса)): перезапускается только интерфейс; правила межсетевого экрана, Fail2Ban и службы не затрагиваются.
- Язык экспорта HTML и TXT, независимый от языка интерфейса.
- Изменяемые папки экспорта и снимков экрана, с очисткой после подтверждения.
- Доступно из главного меню (`9. НАСТРОЙКИ`) или напрямую по клавише `s`.

### 10. Справка

- **Руководство по справке**: все справочные карточки собраны в порядке меню, каждая карточка открывает связанные карточки.
- **FAQ**: реальные вопросы, возникшие при использовании (правила других инструментов, восстановление, Fail2Ban, логи, экспорты и браузер).
- Экспорт руководства и FAQ в HTML на языке экспортов.
- Клавиша `a` по-прежнему открывает справку текущего экрана.

## Архитектура

```text
src/omega_fire/
├── app/              Bootstrap и контейнер внедрения зависимостей
├── core/             Возможности, перечисления и исключения
├── domain/           Чистая бизнес-логика: правила, IP, jail'ы, логи
├── application/      Оркестрация: commands и queries
├── infrastructure/   Бэкенды, хранилище, экспорт, логи и системные датчики
├── ports/            Контракты Protocol/ABC
├── interfaces/       interfaces/tui/ (Textual, по умолчанию) + interfaces/cli/ (Rich, --legacy-cli)
├── plugins/          Встроенные расширения: nftables, iptables, Fail2Ban, conntrack
└── shared/           Парсинг, сеть, форматирование и сквозные утилиты
```

### Принципы проектирования

- `domain/` не содержит ни I/O, ни зависимости от инфраструктуры.
- `application/` оркестрирует сценарии использования через домен и порты — экраны Textual и действия интерфейса Rich вызывают одни и те же commands/queries, бизнес-логика не зависит ни от одного из двух интерфейсов.
- `infrastructure/` — единственный слой, которому разрешено вызывать `nft`, `iptables`, `fail2ban-client` и другие внешние инструменты (subprocess, pty, файлы).
- `interfaces/` не должен напрямую вызывать `subprocess`.
- `ports/` определяет контракты, ожидаемые адаптерами.
- `core/` предоставляет реестр возможностей, используемый разными слоями.
- Плагины позволяют добавлять или развивать бэкенды без изменения бизнес-домена.
- Интерфейс Textual (`interfaces/tui/`) опирается на [`omega-lib`](https://github.com/) (зависимость, общая для всей линейки OMEGA: тема на 9 токенах, определение терминала, общие контракты портов), не опубликованную на PyPI — вендорится в распространяемом архиве (`vendor/omega-lib/`, см. [Установка](#установка)).
- Любой потенциально медленный вызов (бэкенд межсетевого экрана, `fail2ban-client`, диск), запущенный с экрана Textual, выполняется в фоновой задаче (потоке), никогда в главном потоке интерфейса — дашборд или форма остаются отзывчивыми во время операции, вместо того чтобы замораживать всё приложение.

### Структура данных

Omega-Fire использует SQLite через стандартную библиотеку `sqlite3`, без внешней ORM. Основные наборы данных касаются банов, правил, событий аудита и снапшотов.

Миграции версионируются и применяются автоматически при запуске.

## Требования

### Система

- Linux, преимущественно Arch Linux и совместимые дистрибутивы.
- Python 3.10 или выше.
- Права root, доступные через `sudo`.
- Менеджер служб: systemd, runit или OpenRC.
- Хотя бы один бэкенд межсетевого экрана: nftables или iptables.
- Терминал размером не менее 80x24 (см. [Темы и терминалы](#темы-и-терминалы) для подробностей о профилях рендеринга в зависимости от доступного размера).

### Зависимости Python

Производственные зависимости определены в `requirements.txt`:

- `textual` — интерфейс TUI по умолчанию.
- `omega-lib` — тема, определение терминала и контракты, общие для линейки OMEGA (не опубликована на PyPI, см. [Архитектура](#архитектура) и [Установка](#установка)).
- `rich` — рендеринг интерфейса `--legacy-cli` и некоторых отчётов.
- `psutil` — системная информация (CPU, память, сеть, процессы) для дашборда и диагностики.
- `jinja2` — генерация HTML-экспортов.
- `python-dotenv` — переменные окружения.
- `pyte` — эмулятор виртуального терминала, для инкапсуляции `lnav` (меню 8.6 и просмотрщик lnav в 5.2 / 5.3).

Инструменты качества (`pytest`, `black`, `flake8`, `mypy`) перечислены закомментированными в `requirements.txt`: раскомментируйте их или установите отдельно, если вы участвуете в разработке проекта (см. [Тесты и качество кода](#тесты-и-качество-кода)).

### Рекомендуемые опциональные инструменты

Приложение работает в деградированном режиме, если эти инструменты отсутствуют:

- `fail2ban` — автоматизированный бан.
- `conntrack` или `conntrack-tools` — активные соединения и сетевая статистика.
- `lnav` — расширенный анализ логов с несколькими файлами.

На Arch Linux и производных:

```bash
sudo pacman -S fail2ban conntrack-tools lnav
```

## Установка

Официальный архив предоставляется в формате `.tar.gz`. Проверьте его целостность перед установкой:

```bash
sha256sum omega-fire.tar.gz
```

> ⚠️ **Эти три метода предназначены только для первой установки.** Если `~/omega-fire` уже существует (обновление предыдущей версии), используйте раздел [Обновление](#обновление) ниже — никогда не запускайте эти команды изнутри уже существующей папки `omega-fire`: `tar` попытается создать вложенную `omega-fire/omega-fire/` и завершится ошибками доступа, если эта папка принадлежит root (часто случается, если предыдущая распаковка была ошибочно выполнена через `sudo tar`).

Запуск:

```bash

Запустите ./omega-fire.sh."

### Метод 3 — подробная установка

```bash
# 0. Убедиться, что мы не запускаем это изнутри существующей папки omega-fire
[ "$(basename "$PWD")" = "omega-fire" ] && { echo "❌ Похоже, вы уже находитесь внутри папки omega-fire — см. раздел Обновление README." >&2; exit 1; }

# 1. Распаковать
[ -d omega-fire ] && echo "ℹ️ Уже распаковано здесь, шаг пропущен." || tar -xzf omega-fire.tar.gz

# 2. Переместить в домашнюю папку
[ -d ~/omega-fire ] && echo "ℹ️ ~/omega-fire уже существует, перемещение пропущено." || mv omega-fire ~/

# 3. Войти в проект
cd ~/omega-fire/

# 4. Создать виртуальное окружение
[ -d .venv ] && echo "ℹ️ .venv уже существует, создание пропущено." || python3 -m venv .venv

# 5. Установить зависимости (omega-lib вендорена, если присутствует, перед requirements.txt)
source .venv/bin/activate
[ -d vendor/omega-lib ] && pip install -q -e vendor/omega-lib
pip install -r requirements.txt

# 6. Сделать launcher исполняемым
chmod +x omega-fire.sh

# 7. Подготовить var/ для root и текущего пользователя
mkdir -p var
getent group omega-fire >/dev/null 2>&1 || sudo groupadd omega-fire
groups "$USER" 2>/dev/null | grep -qw omega-fire || sudo usermod -aG omega-fire "$USER"
sudo chgrp -R omega-fire var
sudo chmod -R 2775 var

# 8. Запустить
./omega-fire.sh
```

`vendor/omega-lib/` присутствует только в официальном архиве (`build-release.sh` включает её туда автоматически, поскольку omega-lib не опубликована на PyPI); в клоне для разработки установите её отдельно из собственного репозитория (`pip install -e путь/к/omega-lib`).

Выделенная группа и бит `setgid` позволяют root и пользователю совместно использовать файлы, создаваемые в `var/`, не открывая права всей системе. Может потребоваться новое подключение или `newgrp omega-fire`, чтобы немедленно воспользоваться членством в группе.

### Обновление

Если `~/omega-fire` уже существует (предыдущая установка), **никогда не запускайте команды установки изнутри этой папки**: `tar` попытается создать вложенную `omega-fire/omega-fire/` и завершится ошибкой, обычно с каскадом ошибок «Permission denied», если папка принадлежит `root` (часто случается, если предыдущая распаковка была ошибочно выполнена через `sudo tar`).

Рекомендуемая процедура, из любой папки **кроме `~/omega-fire`** (обычно из `~`):

```bash
# 1. Проверить состояние и владельца существующей установки
ls -ld ~/omega-fire

# 2. Отложить старую установку в сторону, а не перезаписывать её
sudo mv ~/omega-fire ~/omega-fire.old-$(date +%Y%m%d)

# 3. Распаковать новый архив прямо в домашнюю папку
tar -xzf omega-fire.tar.gz -C ~/

# 4. Переустановить (пересоздаёт venv, переустанавливает зависимости, заново настраивает права var/)
cd ~/omega-fire
chmod +x install.sh
./install.sh

# 5. Запустить
./omega-fire.sh
```

Шаг 4 (`./install.sh`) автоматически обнаруживает эту ситуацию (пустой `var/db/` здесь, папка `~/omega-fire.old-ГГГГММДД` найдена рядом) и **сам восстанавливает всё** — `config/omega-fire.conf`, базу данных, чёрный список, резервные копии, экспорты и скриншоты из старой установки — без единого вопроса, без ручного шага. Больше ничего не нужно делать, кроме шагов 1–5 выше, независимо от того, что содержала ваша предыдущая установка.

Если рядом обнаружено несколько папок, похожих на предыдущую установку (неоднозначно), `install.sh` никогда не угадывает: он выводит их пути и предлагает самостоятельно запустить `sudo ./migrate-state.sh <папка>` после того, как вы определите нужный источник.

После подтверждения работоспособности новой установки старую папку `~/omega-fire.old-ГГГГММДД` можно удалить (`sudo rm -rf ~/omega-fire.old-ГГГГММДД`).

## Использование

### Запуск

```bash
cd ~/omega-fire
./omega-fire.sh

# или просто, если алиас был создан:
fire
```

Launcher:

1. Проверяет права root и перезапускает через `sudo` при необходимости.
2. Определяет `.venv`, `venv` или системный Python.
3. Настраивает `PYTHONPATH` на `src/`.
4. Запускает `python -m omega_fire` — интерфейс **Textual**, по умолчанию.

Чтобы вместо этого запустить старый интерфейс Rich (последовательный ввод номеров):

```bash
./omega-fire.sh --legacy-cli
```

Старый интерфейс остаётся интерфейсом версии 3.0, на французском: исходное меню 5 (без Библиотеки, Избранного и Классического просмотрщика), без «Просмотр всех экспортов», без руководства по справке и FAQ, без пресетов. Интерфейс Textual содержит полную версию 3.5.

### Языки интерфейса

17 языков: французский, английский, испанский, португальский (Бразилия), итальянский, немецкий, нидерландский, польский, русский, китайский, вьетнамский, тайский, индонезийский, японский, корейский, хинди, арабский. Выбор в настройках (клавиша `s`, « Langue / Language », подпись никогда не переводится), применяется перезапуском только интерфейса, или разово `OMEGA_FIRE_LANG=ru ./omega-fire.sh` (скрипт запуска сохраняет её через `sudo`). В текстовой консоли Linux (TTY) языки, письменности которых нет в консольных шрифтах (вьетнамский, китайский, тайский, японский, корейский, хинди, арабский), на время сеанса показываются на английском. Арабский отображается справа налево. На хинди Terminator, GNOME Terminal, Xfce Terminal и Alacritty показывают текст выровненным; терминалы, которые сами собирают связанные буквы (Kitty, Ghostty, Konsole), могут сдвигать рамки и столбцы. **Язык экспорта** (отчёты HTML и TXT) настраивается отдельно, по умолчанию « Как интерфейс ». Журнал приложения и история аудита по-прежнему записываются на французском; заголовки истории показываются на выбранном языке. Старый интерфейс (`--legacy-cli`) остаётся на французском.

### Общий сценарий работы

1. Экран запуска (splash), затем предупреждение, если терминал слишком мал.
2. Определение системных возможностей (выделенный экран, неблокирующий).
3. Главное меню: 8 тематических разделов (1-8), настройки (9) и справка (10).
4. Выбор раздела, затем действия — каждое действие открывает форму, все обязательные поля которой проверяются перед продолжением.
5. Явное подтверждение перед любой чувствительной или разрушительной операцией (очистка, полная очистка, восстановление...).
6. Выполнение в фоновой задаче для медленных операций (интерфейс остаётся пригодным для использования во время ожидания), затем возврат в меню со сводкой результата.

### Навигация

- Стрелки вверх/вниз: перемещение курсора в списке или меню.
- Tab / Shift+Tab: переход между полями формы.
- Enter: выбрать или подтвердить.
- Клик по строке таблицы: выбрать её и предзаполнить связанные поля (источник для закладки, целевой jail и т. д.).
- `Esc`: вернуться на предыдущий экран (запрашивает подтверждение выхода с главного экрана).
- `a`: контекстная справка — описывает текущее действие или все действия текущего раздела, если экран действия ещё не открыт; полное руководство и FAQ находятся в меню 10.
- `t`: переключиться на следующую тему без подтверждения.
- `r`: повторно определить размер и семейство терминала.
- `s`: открыть настройки (тема, профиль рендеринга, языки, папки).
- `q` / `Ctrl+Q`: выйти, с подтверждением.

#### Особенности экрана lnav (8.6 и просмотрщик lnav в 5.2 / 5.3)

`lnav` инкапсулирован в псевдотерминал с постоянными header/footer Omega-Fire вокруг его собственного представления, чтобы избежать любых коллизий между его собственными сочетаниями клавиш и сочетаниями Omega-Fire:

- Стрелки ↑↓: навигация по логам (собственное сочетание `lnav`, передаётся как есть).
- Стрелки ←→: горизонтальная прокрутка длинных строк (собственное сочетание `lnav`).
- `g` / `G`: перейти в начало / в конец (собственное сочетание `lnav`).
- `Ctrl+C`: отметить текущую строку и скопировать её в системный буфер обмена (заменяет собственную команду копирования `lnav`, которая может зависать в некоторых системах).
- строчная `t`: следующая тема, своя для этого представления (заглавная `T` остаётся собственным сочетанием `lnav` для отображения времени, прошедшего между строками).
- `Ctrl+Q`: вернуться в Omega-Fire (корректно закрывает `lnav`, не завершая приложение).

## Темы и терминалы

Десять тем `omega-*` являются общими для всей линейки OMEGA:

```text
omega-base       omega-dark       omega-light
omega-neon       omega-burn       omega-pink
omega-hack       omega-contrast   omega-mono
omega-minimal
```

- Переключайтесь между темами клавишей `t` или выбирайте тему напрямую из настроек (`s`).
- Выбранная тема сохраняется и восстанавливается при следующем запуске.
- Omega-Fire автоматически адаптирует визуальную сложность (рамки, splash, плотность информации) к обнаруженному терминалу через **профиль рендеринга**: Полный, Стандартный, Уменьшенный или Моно (только ASCII). Профиль можно вручную переопределить в настройках.

| Минимальный размер | Профиль | Типичные терминалы |
|---|---|---|
| 120×32 и более | Полный | Ghostty, Alacritty, WezTerm, Kitty |
| 100×28 и более | Стандартный | Konsole, GNOME Terminal, Terminator, xfce4-terminal |
| 80×24 и более | Уменьшенный | urxvt, xterm, современный SSH |
| менее 80×24 | Моно (только ASCII) | Linux TTY, устаревший SSH |

Ниже 80×24 запуск отклоняется (требуется минимальный размер); измените размер терминала и перезапустите, либо используйте `r` после изменения размера, если отображение не обновилось автоматически.

## Настройка

Специфическую конфигурацию можно изменить в:

```text
omega-fire/config/omega-fire.conf
```

Она может, в частности, определять:

- пути к журналам;
- серверы и источники мониторинга;
- доступные бэкенды или пользовательские пути;
- анализируемые окружения;
- параметры, адаптированные под конкретную установку.

Конфигурация перечитывается при перезапуске или при ручном пересканировании (меню 1.3 или 7.4).

Этот файл полностью необязателен (приложение нормально работает и без него, с переходом на переменные окружения) и **исключён из дистрибутивного архива** — обновление никогда не перезаписывает его молча, а `install.sh` сам автоматически восстанавливает его из предыдущей установки, если это применимо (см. «Обновление» выше).

### Внутренние пути и системные пути

По умолчанию Omega-Fire работает в собственной папке:

```text
var/exports/       # внутренняя папка проекта
/var/exports/      # абсолютный системный путь
```

Начальный символ `/` таким образом значим. Импорт и экспорт в систему должны явно запрашиваться пользователем.

## Бэкенды и совместимость

Omega-Fire определяет компоненты и активирует только используемые функции.

| Компонент | Роль | Статус |
|---|---|---|
| nftables | Современный межсетевой экран IPv4/IPv6 | Рекомендуется |
| iptables | Межсетевой экран IPv4 | Совместим |
| ip6tables | Межсетевой экран IPv6 с iptables | Совместим при наличии |
| Fail2Ban | Jail'ы и автоматизированные баны | Опционально |
| conntrack | Активные соединения | Опционально |
| lnav | Расширенный анализ логов | Опционально |
| systemd, runit, OpenRC | Управление службами | Автоматическое определение |
| Docker, VNC, серверы | Обнаруженные приложения и службы | В зависимости от установки |

### IPv4 и IPv6

Оба семейства адресов поддерживаются совместимыми бэкендами:

- nftables: IPv4 и IPv6 в dual stack;
- iptables/ip6tables: в зависимости от доступных бинарников;
- Fail2Ban: в зависимости от конфигурации jail и системы.

Длинные, сжатые, локальные, смешанные форматы IPv6, с нулями и в нотации CIDR обрабатываются соответствующими компонентами.

## Хранение данных, логи и экспорт

### Хранение данных

- SQLite через `sqlite3`.
- Таблицы, относящиеся к банам, правилам, аудиту и снапшотам.
- Версионированные миграции применяются автоматически.
- Архивы полного состояния в формате `.tar.gz`.
- Закладки (избранные источники логов) и недавняя история сохраняются в JSON (`var/runtime/`), переживают перезапуск.

### Журналы

- Текстовый прикладной журнал: `var/logs/app.log`.
- Структурированный JSON-журнал аудита, в частности с `event_type`, `actor`, `action`, `result` и `details`.

### Экспорт

Экспорты доступны в JSON, TXT и HTML, с несколькими CSS-темами для HTML-отчётов.

## Безопасность

Omega-Fire воздействует на критические компоненты системы и должен использоваться с осторожностью.

- Запуск требует прав root через `sudo`.
- Полная очистка, общая очистка и применение политики могут быть разрушительными.
- Предустановленная политика запускает автоматическое резервное копирование перед изменением.
- В iptables / ip6tables применение политики или очистка бэкенда стирает и правила других инструментов (UFW…): Omega-Fire предупреждает об этом и даёт выбрать перед действием.
- Выполняйте ручное резервное копирование перед каждым важным изменением.
- Проверяйте реальное состояние межсетевого экрана, jail'ов и соединений после каждой операции.
- Сначала тестируйте на одноразовой машине или цели.
- Используйте документационные сети RFC 5737 для тестов IPv4: `192.0.2.0/24`, `198.51.100.0/24` и `203.0.113.0/24`.
- Проверяйте экспорты и снапшоты перед восстановлением на продуктивной машине.
- Не предоставляйте папке `var/` больше прав, чем необходимо.

## Тесты и качество кода

Набор содержит 137 модульных тестов (более 8000 проверенных случаев): предметная область, оркестрация (`application/`), инфраструктура, а также экраны Textual, добавленные или исправленные в 3.5, запускаемые с реальными таблицами стилей (вёрстка, полные сценарии, языки экспортов). Этот архив не содержит папку `tests/`: получите её из вашего репозитория разработки, если нужно её запустить.

```bash
source .venv/bin/activate
python -m unittest discover -s tests/unit -t .
```

Многослойная архитектура строго отделяет предметную область от представления (`domain/`, `application/`, `ports/` как `Protocol`, см. [Архитектура](#архитектура)): большинству тестов не нужны ни root, ни настоящий файрвол.

Если вы участвуете в разработке проекта, установите инструменты качества, объявленные (закомментированными) в `requirements.txt`:

```bash
pip install pytest pytest-cov black flake8 mypy
```

Доступные инструменты после установки:

```bash
black .
flake8 .
mypy src/
pytest --cov
```

## Состояние проекта

### Рабочие пункты

- Единый TUI Textual для основных механизмов сетевой безопасности, проверенные формы, темы и контекстная справка, общие с линейкой OMEGA.
- Исторический интерфейс Rich сохранён как запасной вариант (`--legacy-cli`).
- Автоматическое определение возможностей.
- Управление доступными бэкендами.
- Поддержка IPv4/IPv6 в зависимости от присутствующих инструментов.
- Прикладное журналирование и аудит.
- Резервное копирование и восстановление.
- Экспорты JSON, TXT и HTML.
- Дашборд и статистика, обновляемые в фоновой задаче без блокировки интерфейса.
- Задокументированная многослойная архитектура.

### Известные ограничения

- Набор тестов покрывает экраны Textual версии 3.5, но пока не все более старые экраны (см. [Тесты и качество кода](#тесты-и-качество-кода)).
- Механизм `ExecutionPlan`/`PipelineStep` частично сохранён в проекте.
- Точная доступность функций зависит от бинарников, служб, прав доступа и конфигураций хост-машины.
- Исторический интерфейс Rich (`--legacy-cli`) больше не является активным направлением разработки; он сохранён на время полной стабилизации интерфейса Textual в реальных условиях.

## Удаление

Если данные остались в папке проекта:

```bash
sudo rm -rf ~/omega-fire
```

Вручную удалите файлы, экспортированные в другое место, возможные алиасы `fire`, добавленные в `~/.bashrc` или `~/.zshrc`, а также выделенную группу, если она больше не используется:

```bash
sudo groupdel omega-fire
```

Выполняйте эту последнюю команду только если ни один другой файл или служба не зависит от этой группы.
