**Omega-Fire** เป็นแอปพลิเคชัน TUI (Terminal User Interface) เขียนด้วย Python และสร้างด้วย [Textual](https://github.com/Textualize/textual) โดยให้อินเทอร์เฟซเดียวจากเทอร์มินัลสำหรับดูแลไฟร์วอลล์ Linux, Fail2Ban, ที่อยู่ที่ถูกแบน, กฎเครือข่าย, ล็อก และสถิติของระบบ

อินเทอร์เฟซ Textual เป็นโหมดการทำงานเริ่มต้น ใช้งานผ่านเมนู แบบฟอร์มที่ผ่านการตรวจสอบ (ทุกช่องที่จำเป็นจะถูกตรวจก่อนไปต่อ) และหน้าจอเฉพาะ พร้อมธีม ความช่วยเหลือตามบริบท และคีย์ลัดที่ใช้ร่วมกับส่วนอื่นของชุด OMEGA (omega-check, omega-deep, omega-stress...) อินเทอร์เฟซ [Rich](https://github.com/Textualize/rich) แบบเดิมที่ทำงานเป็นลำดับและควบคุมด้วยการพิมพ์ตัวเลข ยังใช้ได้ผ่าน `--legacy-cli` (ดู [การเปิดใช้งาน](#การเปิดใช้งาน)) 
ตัวอย่าง: [ภาพหน้าจอ](https://kraynux.snake-mackarel.ts.net/omega-fire/screenshots/index-2.html)

โปรเจกต์นี้ออกแบบตามหลักการ **Clean Architecture** โดยแยกโดเมนธุรกิจ การประสานงาน โครงสร้างพื้นฐาน และส่วนติดต่อผู้ใช้อย่างชัดเจน

## ภาพรวม

Omega-Fire ทำหน้าที่เป็น **ศูนย์ควบคุมภายในเครื่อง** สำหรับความปลอดภัยเครือข่าย โดยจะตรวจหาส่วนประกอบที่มีอยู่บนเครื่องโดยอัตโนมัติ และปรับเมนูให้ตรงกับความสามารถที่ใช้ได้จริง

### เป้าหมาย

- รวม nftables, iptables, ip6tables และ Fail2Ban ไว้ในอินเทอร์เฟซที่สอดคล้องกัน
- ช่วยให้สังเกตและจัดการการเชื่อมต่อ การแบน และเหตุการณ์ของระบบได้ง่ายขึ้น
- รวมศูนย์การส่งออก การสำรองข้อมูล การตรวจสอบ และประวัติการดำเนินการ
- รักษาสถาปัตยกรรมที่ทดสอบได้และขยายได้
- ทำงานในโหมดลดความสามารถเมื่อไม่มีส่วนประกอบเสริม

### สิ่งที่ Omega-Fire ทำ

- ตรวจหาแบ็กเอนด์ บริการ เคอร์เนล และเครื่องมือที่มีอยู่
- ดูแล nftables, iptables และ ip6tables เมื่อมีส่วนประกอบเหล่านี้
- จัดการ IP ที่ถูกแบน ทีละรายการหรือเป็นชุด พร้อมการนำเข้า ส่งออก ซิงโครไนซ์ และ flush
- สร้าง แสดงรายการ และลบกฎขั้นสูง
- ใช้นโยบายที่กำหนดไว้ล่วงหน้าพร้อมสำรองข้อมูลอัตโนมัติก่อน
- ดูแล jail ของ Fail2Ban และการแบนของมัน
- วิเคราะห์ล็อกแบบสดหรือในรูปแบบสถิติ
- ให้การเฝ้าระวังในรูปแบบการมอนิเตอร์
- ใช้ conntrack เพื่อแสดงการเชื่อมต่อที่ใช้งานอยู่เมื่อมีให้ใช้
- สร้างไฟล์ส่งออก JSON, TXT และ HTML
- สำรองและกู้คืนสถานะทั้งหมดในไฟล์เก็บถาวร `.tar.gz`
- บันทึกการดำเนินการลงในล็อกของแอปพลิเคชันและการตรวจสอบ JSON แบบมีโครงสร้าง
- เฝ้าดูบริการและแอปพลิเคชันที่ตรวจพบ: systemd, runit, OpenRC, Docker, เซิร์ฟเวอร์, VNC เป็นต้น

### สิ่งที่โปรเจกต์ไม่ได้ทำ

- ไม่ได้แทนที่ nftables, iptables หรือ Fail2Ban
- ไม่ใช่ไฟร์วอลล์อิสระที่แยกจากระบบ
- ไม่มีการยืนยันตัวตนแบบหลายผู้ใช้
- ไม่เปิด API เครือข่ายในการทำงานปกติ
- ไม่ใช่แดชบอร์ดเว็บ
- ไม่ได้ปกป้องเครื่องระยะไกลโดยตรงจากอีกเครื่องหนึ่ง
- โดยค่าเริ่มต้น ไม่ติดตั้งไฟล์ใดนอกโฟลเดอร์ของตัวเอง
- ไม่รับประกันว่าทุกแบ็กเอนด์จะมีในทุกดิสทริบิวชัน

## ฟีเจอร์

### 1. ความสามารถและการวินิจฉัย

- แสดงทะเบียนความสามารถที่ตรวจพบ
- ดูรายละเอียดของความสามารถตามตัวระบุ
- สแกนระบบใหม่ด้วยตนเองหลังติดตั้งส่วนประกอบ
- ดูผลการวินิจฉัยล่าสุด
- ดูและค้นหาในล็อกของแอปพลิเคชัน
- ส่งออกสถานะและผลการวินิจฉัยเป็น JSON, TXT หรือ HTML

### 2. การจัดการ IP แบบรวมศูนย์

blacklist แบบรวมศูนย์ช่วยให้ทำงานกับ nftables และ iptables ได้จากหน้าจอเดียว

- แบน IP เดียวหรือรายการ IP
- ยกเลิกการแบนทีละรายการหรือเป็นชุด
- ป้อนโดยตรงหรือนำเข้าจากไฟล์
- แสดงรายการตามแบ็กเอนด์หรือมุมมองรวม
- ซิงโครไนซ์ระหว่างแบ็กเอนด์ NFTables/IPTables
- ส่งออกและนำเข้ารายการอีกครั้ง
- ล้างแบ็กเอนด์หนึ่งรายการหรือหลายรายการทั้งหมด
- รองรับ IPv4 และ IPv6
- จัดการไฟล์ blocklist (`var/blocklist/`) และรายการที่ปักหมุดไว้ได้โดยตรงจากหน้าจอเฉพาะ

### 3. การจัดการกฎและนโยบาย

- ตัวช่วยทีละขั้นตอนสำหรับสร้างกฎขั้นสูง
- รายการกฎของระบบและกฎที่ Omega-Fire สร้าง
- ลบกฎด้วยการเลือก
- ล้างกฎที่ไม่ใช้งานในฐานอ้างอิงโดยอัตโนมัติ
- ใช้นโยบายที่กำหนดไว้ล่วงหน้า
- สำรองข้อมูลอัตโนมัติก่อนใช้นโยบาย
- ปรับแต่ง บันทึก และกู้คืนนโยบาย
- ระบุนโยบายที่ใช้งานอยู่ในเมนูสถานะและแดชบอร์ด
- ทำเครื่องหมายโปรไฟล์ที่ถูกแก้ไขในรูปแบบ `โปรไฟล์ + CUSTOM`
- การจัดการตาราง (เมนู 3.5): การวินิจฉัยแบบอ่านอย่างเดียวตามแบ็กเอนด์ (การมีอยู่ของตาราง นโยบาย input/output/forward จำนวนกฎ) พร้อมตรวจหาความแตกต่างระหว่างแบ็กเอนด์
- สร้างตาราง nftables เมื่อใช้งานครั้งแรก โดยไม่เขียนทับ chain ที่กำหนดค่าไว้แล้ว
- รีเซ็ตนโยบาย chain เป็น ACCEPT บนแบ็กเอนด์ เพื่อแก้นโยบายแบบจำกัดที่ค้างอยู่จากโปรไฟล์ก่อนหน้า
- ล้างแบ็กเอนด์แบบเจาะจง หรือล้างทุกแบ็กเอนด์ที่ตรวจพบแบบซิงโครไนซ์ในการทำงานครั้งเดียว
- ลบตาราง nftables ทั้งหมด (การทำงานขั้นสูง นอกเหนือจากการลบกฎเพียงอย่างเดียว)

### 4. การจัดการ Fail2Ban

- สถานะโดยละเอียดของ jail และพารามิเตอร์
- จำนวน IP ที่ถูกแบนและข้อมูล rate-limit
- ค้นหา IP ใน jail
- ban และ unban ทีละรายการหรือหลายรายการ
- โอนย้าย IP ระหว่าง jail แบ็กเอนด์ และไฟล์
- สร้าง jail แบบกำหนดเองพร้อมคำแนะนำ
- แม่แบบ jail ที่กำหนดไว้ล่วงหน้า
- ลบ jail
- ล้าง jail หรือล้างทั้งหมด
- ส่งออกเป็น JSON, TXT หรือ HTML
- ตรวจสอบและตรวจประเมินการกำหนดค่า
- ควบคุมบริการ: สถานะ เริ่ม หยุด เริ่มใหม่ เปิดและปิดตอนบูต

### 5. ล็อกและการบำรุงรักษา

- Live Tail พร้อมแดชบอร์ดของ Omega-Fire
- แสดงหลายไฟล์พร้อมรายการปักหมุด (แหล่งโปรด ที่จำไว้ระหว่างการเปิดใช้สองครั้ง)
- การผสานรวม `lnav`: เลือกไฟล์หนึ่งหรือหลายไฟล์ (หมายเลขหรือพาธที่พิมพ์เอง คั่นด้วยจุลภาค) รวมเป็นมุมมองตามลำดับเวลาเดียวโดยอัตโนมัติ ห่อด้วย header/footer ของ Omega-Fire (ดู [การนำทาง](#การนำทาง))
- วิเคราะห์ IP ที่พบบ่อยที่สุดด้วย Top N
- ลบ IP แบบเจาะจงในไฟล์ LOG หรือ TXT
- หมุนเวียนและสำรองข้อมูลทันทีหรืออัตโนมัติ
- กู้คืนข้อมูลสำรอง
- ล้างตามอายุ โควตา ประเภท หรือการเลือกเอง
- ล้างขั้นสูงตามโฟลเดอร์หรือสภาพแวดล้อม
- สถิติ 24 ชั่วโมง 7 วัน หรือ 30 วัน
- วิเคราะห์เหตุการณ์ ความเคลื่อนไหว โควตา และ IP ที่อยู่ใน jail

### 6. การส่งออกและรายงาน

รูปแบบที่มี:

- **JSON**: ข้อมูลแบบมีโครงสร้างที่นำกลับมาใช้ได้
- **TXT**: รูปแบบดิบหรือปรับให้เหมาะกับการนำเข้า
- **HTML**: รายงานที่อ่านง่ายและเป็นภาพ

รายงานที่มี:

- blacklist ฉบับเต็ม
- ruleset แบบมีโครงสร้าง
- กฎที่เลือกตามที่มา: ระบบ, Omega-Fire หรือที่ใช้งานอยู่
- รายงานการตรวจสอบฉบับเต็ม
- สถิติ Fail2Ban
- สถานะและการวินิจฉัยของระบบ
- รายงานสถิติ 7 หรือ 30 วัน

ธีม HTML:

- `omega-base` — น้ำเงินกลางคืนและฟ้าอมเขียว ธีมเริ่มต้น
- `omega-burn` — ถ่านแดงอมส้ม
- `omega-neon` — ไซเบอร์พังก์ฟ้าอมเขียวและม่วงแดง
- `light-basic` — สว่างและเรียบง่าย
- `light-alt` — กระดาษสีครีมและเขียวป่า

### 7. ระบบและการจัดเก็บถาวร

- สำรองสถานะทั้งหมด: กฎ, การแบนของ nftables, การแบนของ iptables และ Fail2Ban
- สร้างไฟล์เก็บถาวร `.tar.gz` พร้อมประทับเวลา
- แสดงรายการและกู้คืน snapshot
- ประวัติการดำเนินการ
- กรองและล้างประวัติ
- โหลดการกำหนดค่าใหม่และสแกนใหม่โดยไม่ต้องเริ่มใหม่

### 8. การมอนิเตอร์และสถิติ

- แดชบอร์ดแบบเรียลไทม์ที่รีเฟรชเป็นระยะ (ทุก 2 วินาที) โดยไม่บล็อกอินเทอร์เฟซระหว่างเก็บข้อมูล
- แสดงนโยบายที่ใช้งานอยู่
- การเชื่อมต่อที่ใช้งานอยู่ผ่าน conntrack
- ทราฟฟิก เหตุการณ์ สถิติ และล็อกของเซิร์ฟเวอร์
- รายงานรวม 7 และ 30 วัน
- ส่งออก snapshot และรายงานเป็น HTML

### 9. การตั้งค่า

- เลือกธีมที่ใช้งานจากธีม `omega-*` สิบแบบที่ใช้ร่วมกับส่วนอื่นของชุด (ดู [ธีมและเทอร์มินัล](#ธีมและเทอร์มินัล)) ซึ่งจำไว้ระหว่างการเปิดใช้สองครั้ง
- กำหนดโปรไฟล์การแสดงผลด้วยตนเอง (อัตโนมัติ เต็ม มาตรฐาน ลดทอน หรือ mono เท่านั้น) มีผลในการเปิดใช้ครั้งถัดไป
- เข้าถึงได้จากเมนูหลัก (`9. RÉGLAGES`) หรือโดยตรงด้วยปุ่ม `s`

## สถาปัตยกรรม

```text
src/omega_fire/
├── app/              Bootstrap และคอนเทนเนอร์สำหรับ dependency injection
├── core/             ความสามารถ การแจงนับ และข้อยกเว้น
├── domain/           ตรรกะธุรกิจล้วน: กฎ, IP, jail, ล็อก
├── application/      การประสานงาน: commands และ queries
├── infrastructure/   แบ็กเอนด์ การจัดเก็บ การส่งออก ล็อก และเซนเซอร์ของระบบ
├── ports/            สัญญา Protocol/ABC
├── interfaces/       interfaces/tui/ (Textual, ค่าเริ่มต้น) + interfaces/cli/ (Rich, --legacy-cli)
├── plugins/          ส่วนขยายในตัว: nftables, iptables, Fail2Ban, conntrack
└── shared/           การแยกวิเคราะห์ เครือข่าย การจัดรูปแบบ และเครื่องมือที่ใช้ร่วมกัน
```

### หลักการออกแบบ

- `domain/` ไม่มี I/O และไม่ขึ้นกับโครงสร้างพื้นฐาน
- `application/` ประสานงานกรณีการใช้งานผ่านโดเมนและ port — หน้าจอ Textual และการทำงานของอินเทอร์เฟซ Rich เรียก commands/queries ชุดเดียวกัน และตรรกะธุรกิจไม่ขึ้นกับอินเทอร์เฟซใดในสองแบบ
- `infrastructure/` เป็นชั้นเดียวที่ได้รับอนุญาตให้เรียก `nft`, `iptables`, `fail2ban-client` และเครื่องมือภายนอกอื่น ๆ (subprocess, pty, ไฟล์)
- `interfaces/` ต้องไม่เรียก `subprocess` โดยตรง
- `ports/` กำหนดสัญญาที่อะแดปเตอร์คาดหวัง
- `core/` ให้ทะเบียนความสามารถที่ชั้นต่าง ๆ ใช้
- ปลั๊กอินช่วยให้เพิ่มหรือพัฒนาแบ็กเอนด์ได้โดยไม่ต้องแก้ไขโดเมนธุรกิจ
- อินเทอร์เฟซ Textual (`interfaces/tui/`) อาศัย [`omega-lib`](https://github.com/) (การพึ่งพาที่ใช้ร่วมกันทั้งชุด OMEGA: ธีม 9 โทเค็น การตรวจหาเทอร์มินัล สัญญา port ร่วม) ซึ่งไม่ได้เผยแพร่บน PyPI — รวมไว้ในไฟล์แจกจ่าย (`vendor/omega-lib/` ดู [การติดตั้ง](#การติดตั้ง))
- ทุกการเรียกที่อาจช้า (แบ็กเอนด์ไฟร์วอลล์, `fail2ban-client`, ดิสก์) ที่เริ่มจากหน้าจอ Textual จะทำงานเบื้องหลัง (thread) ไม่ใช่บน thread หลักของอินเทอร์เฟซ — แดชบอร์ดหรือแบบฟอร์มจึงยังตอบสนองระหว่างการทำงาน แทนที่จะทำให้ทั้งแอปพลิเคชันค้าง

### โครงสร้างข้อมูล

Omega-Fire ใช้ SQLite ผ่านไลบรารีมาตรฐาน `sqlite3` โดยไม่มี ORM ภายนอก ชุดข้อมูลหลักเกี่ยวกับการแบน กฎ เหตุการณ์การตรวจสอบ และ snapshot

การย้ายข้อมูล (migration) มีการกำหนดเวอร์ชันและถูกนำไปใช้โดยอัตโนมัติเมื่อเริ่มทำงาน

## การติดตั้ง

ไฟล์เก็บถาวรอย่างเป็นทางการอยู่ในรูปแบบ `.tar.gz` ตรวจสอบความสมบูรณ์ก่อนติดตั้ง:

```bash
sha256sum omega-fire.tar.gz
```

> ⚠️ **สามวิธีนี้ใช้สำหรับการติดตั้งครั้งแรก** หาก `~/omega-fire` มีอยู่แล้ว (อัปเดตจากเวอร์ชันก่อนหน้า) ให้ใช้หัวข้อ [การอัปเดต](#การอัปเดต) ด้านล่าง — อย่ารันคำสั่งเหล่านี้ซ้ำจากภายในโฟลเดอร์ `omega-fire` ที่มีอยู่: `tar` จะพยายามสร้าง `omega-fire/omega-fire/` ซ้อนกันและล้มเหลวด้วยข้อผิดพลาดด้านสิทธิ์ หากโฟลเดอร์นั้นเป็นของ root (พบบ่อยหากเคยแตกไฟล์ด้วย `sudo tar` โดยไม่ตั้งใจ)

```bash
chmod +x install.sh

```

คำสั่งนี้รันซ้ำได้: จะข้ามขั้นตอนที่ทำไปแล้ว

```bash
([ "$(basename "$PWD")" = "omega-fire" ] && { echo "❌ ดูเหมือนคุณอยู่ในโฟลเดอร์ omega-fire อยู่แล้ว — ดูหัวข้อการอัปเดตใน README" >&2; exit 1; }; [ -d ~/omega-fire ] && echo "ℹ️ ~/omega-fire มีอยู่แล้ว ข้ามการแตกไฟล์" || (tar -xzf omega-fire.tar.gz && mv omega-fire ~/)) && cd ~/omega-fire/ && ([ -d .venv ] && echo "ℹ️ มี .venv อยู่แล้ว ข้ามขั้นตอนนี้" || python3 -m venv .venv) && source .venv/bin/activate && ([ -d vendor/omega-lib ] && pip install -q -e vendor/omega-lib || true) && pip install -r requirements.txt && chmod +x omega-fire.sh && mkdir -p var && (getent group omega-fire >/dev/null 2>&1 && echo "ℹ️ มีกลุ่ม omega-fire อยู่แล้ว" || sudo groupadd omega-fire) && (groups "$USER" 2>/dev/null | grep -qw omega-fire && echo "ℹ️ $USER เป็นสมาชิกกลุ่ม omega-fire อยู่แล้ว" || sudo usermod -aG omega-fire "$USER") && sudo chgrp -R omega-fire var && sudo chmod -R 2775 var && echo "✅ ติดตั้ง Omega-Fire แล้ว รัน ./omega-fire.sh"
```

### วิธีที่ 3 — การติดตั้งแบบละเอียด

```bash
# 0. ตรวจสอบว่าไม่ได้รันซ้ำจากภายใน omega-fire ที่มีอยู่
[ "$(basename "$PWD")" = "omega-fire" ] && { echo "❌ ดูเหมือนคุณอยู่ในโฟลเดอร์ omega-fire อยู่แล้ว — ดูหัวข้อการอัปเดตใน README" >&2; exit 1; }

# 1. แตกไฟล์
[ -d omega-fire ] && echo "ℹ️ แตกไฟล์ไว้ที่นี่แล้ว ข้ามขั้นตอนนี้" || tar -xzf omega-fire.tar.gz

# 2. ย้ายไปยังโฮม
[ -d ~/omega-fire ] && echo "ℹ️ ~/omega-fire มีอยู่แล้ว ข้ามการย้าย" || mv omega-fire ~/

# 3. เข้าไปในโปรเจกต์
cd ~/omega-fire/

# 4. สร้างสภาพแวดล้อมเสมือน
[ -d .venv ] && echo "ℹ️ มี .venv อยู่แล้ว ข้ามการสร้าง" || python3 -m venv .venv

# 5. ติดตั้งการพึ่งพา (omega-lib ที่รวมมา ถ้ามี ก่อน requirements.txt)
source .venv/bin/activate
[ -d vendor/omega-lib ] && pip install -q -e vendor/omega-lib
pip install -r requirements.txt

# 6. ทำให้ตัวเปิดใช้งานรันได้
chmod +x omega-fire.sh

# 7. เตรียม var/ สำหรับ root และผู้ใช้ปัจจุบัน
mkdir -p var
getent group omega-fire >/dev/null 2>&1 || sudo groupadd omega-fire
groups "$USER" 2>/dev/null | grep -qw omega-fire || sudo usermod -aG omega-fire "$USER"
sudo chgrp -R omega-fire var
sudo chmod -R 2775 var

# 8. เปิดใช้งาน
./omega-fire.sh
```

`vendor/omega-lib/` มีอยู่เฉพาะในไฟล์เก็บถาวรอย่างเป็นทางการ (`build-release.sh` ใส่ไว้ให้อัตโนมัติ เนื่องจาก omega-lib ไม่ได้เผยแพร่บน PyPI) สำหรับ clone เพื่อการพัฒนา ให้ติดตั้งแยกจากที่เก็บของมันเอง (`pip install -e path/to/omega-lib`)

กลุ่มเฉพาะและบิต `setgid` ช่วยให้ root และผู้ใช้แชร์ไฟล์ที่สร้างใน `var/` ได้โดยไม่ต้องเปิดสิทธิ์ให้ทั้งระบบ อาจต้องเข้าสู่ระบบใหม่หรือใช้ `newgrp omega-fire` เพื่อให้สมาชิกภาพในกลุ่มมีผลทันที

### การอัปเดต

หาก `~/omega-fire` มีอยู่แล้ว (การติดตั้งก่อนหน้า) **อย่ารันคำสั่งติดตั้งซ้ำจากภายในโฟลเดอร์นี้**: `tar` จะพยายามสร้าง `omega-fire/omega-fire/` ซ้อนกันและล้มเหลว มักตามมาด้วยข้อผิดพลาด « Permission denied » ต่อเนื่อง หากโฟลเดอร์เป็นของ `root` (พบบ่อยหากเคยแตกไฟล์ด้วย `sudo tar` โดยไม่ตั้งใจ)

ขั้นตอนที่แนะนำ จากโฟลเดอร์ใดก็ได้ **ที่ไม่ใช่ `~/omega-fire`** (โดยทั่วไปคือ `~` เอง):

```bash
# 1. ตรวจสอบสถานะและเจ้าของของการติดตั้งที่มีอยู่
ls -ld ~/omega-fire

# 2. แยกการติดตั้งเดิมไว้แทนการเขียนทับ
sudo mv ~/omega-fire ~/omega-fire.old-$(date +%Y%m%d)

# 3. แตกไฟล์เก็บถาวรใหม่ลงในโฮมโดยตรง
tar -xzf omega-fire.tar.gz -C ~/

# 4. ติดตั้งใหม่ (สร้าง venv ใหม่ ติดตั้งการพึ่งพาใหม่ ตั้งสิทธิ์ของ var/ ใหม่)
cd ~/omega-fire
chmod +x install.sh
./install.sh

# 5. เปิดใช้งาน
./omega-fire.sh
```

ขั้นตอนที่ 4 (`./install.sh`) ตรวจพบกรณีนี้โดยอัตโนมัติ (ไม่มีฐานข้อมูล `var/db/` ที่นี่ และพบโฟลเดอร์ `~/omega-fire.old-YYYYMMDD` อยู่ข้าง ๆ) และ **กู้คืนเอง** `config/omega-fire.conf` ฐานข้อมูล blocklist ข้อมูลสำรอง ไฟล์ส่งออก และภาพหน้าจอจากการติดตั้งเดิม — โดยไม่ถามและไม่ต้องทำขั้นตอนเอง ไม่ต้องทำอะไรเพิ่มนอกจากข้อ 1 ถึง 5 ด้านบน ไม่ว่าการติดตั้งก่อนหน้าของคุณจะมีอะไรอยู่

หากมีหลายโฟลเดอร์ที่ดูเหมือนการติดตั้งเดิมอยู่ข้าง ๆ (กำกวม) `install.sh` จะไม่เดาใด ๆ: จะแสดงพาธของโฟลเดอร์เหล่านั้นและแนะนำให้คุณรัน `sudo ./migrate-state.sh <โฟลเดอร์>` เองเมื่อระบุแหล่งที่ถูกต้องได้แล้ว

เมื่อยืนยันการติดตั้งใหม่แล้ว สามารถลบโฟลเดอร์เดิม `~/omega-fire.old-YYYYMMDD` ได้ (`sudo rm -rf ~/omega-fire.old-YYYYMMDD`)


ตัวเปิดใช้งาน:

1. ตรวจสอบสิทธิ์ root และเปิดใหม่ผ่าน `sudo` หากจำเป็น
2. ตรวจหา `.venv`, `venv` หรือ Python ของระบบ
3. ตั้งค่า `PYTHONPATH` ไปที่ `src/`
4. รัน `python -m omega_fire` — อินเทอร์เฟซ **Textual** โดยค่าเริ่มต้น

หากต้องการเปิดอินเทอร์เฟซ Rich แบบเดิม (พิมพ์ตัวเลขตามลำดับ) แทน:

```bash
./omega-fire.sh --legacy-cli
```

### ลำดับการใช้งานทั่วไป

1. หน้าจอเริ่มต้น (splash) ตามด้วยคำเตือนหากเทอร์มินัลเล็กเกินไป
2. ตรวจหาความสามารถของระบบ (หน้าจอเฉพาะ ไม่บล็อก)
3. เมนูหลัก: 8 หมวดตามหัวข้อ (1-8) และการตั้งค่า (9)
4. เลือกหมวด แล้วเลือกการทำงาน — ทุกการทำงานจะเปิดแบบฟอร์มที่ตรวจสอบทุกช่องที่จำเป็นก่อนไปต่อ
5. ยืนยันอย่างชัดเจนก่อนการทำงานที่อ่อนไหวหรือทำลายข้อมูล (flush, ล้าง, กู้คืน...)
6. รันการทำงานที่ช้าในเบื้องหลัง (อินเทอร์เฟซยังใช้งานได้ระหว่างรอ) แล้วกลับไปยังเมนูพร้อมสรุปผลลัพธ์

### การนำทาง

- ลูกศรขึ้น/ลง: เลื่อนเคอร์เซอร์ในรายการหรือเมนู
- Tab / Shift+Tab: เลื่อนระหว่างช่องของแบบฟอร์ม
- Enter: เลือกหรือยืนยัน
- คลิกแถวของตาราง: เลือกแถวนั้นและกรอกช่องที่เกี่ยวข้องไว้ล่วงหน้า (แหล่งที่จะปักหมุด, jail เป้าหมาย ฯลฯ)
- `Esc`: กลับไปหน้าจอก่อนหน้า (ขอการยืนยันเมื่อออกจากหน้าหลัก)
- `a`: ความช่วยเหลือตามบริบท — อธิบายการทำงานปัจจุบัน หรือทุกการทำงานของหมวดปัจจุบันหากยังไม่ได้เปิดหน้าจอการทำงาน
- `t`: ไปยังธีมถัดไป โดยไม่ต้องยืนยัน
- `r`: ตรวจหาขนาดและตระกูลของเทอร์มินัลใหม่
- `s`: เปิดการตั้งค่า (ธีม, โปรไฟล์การแสดงผล)
- `q` / `Ctrl+Q`: ออก พร้อมการยืนยัน

#### ลักษณะเฉพาะของหน้าจอ lnav (5.9 / 8.6)

`lnav` ถูกห่อไว้ใน pseudo-terminal พร้อม header/footer ของ Omega-Fire ที่คงอยู่รอบมุมมองของมัน เพื่อป้องกันไม่ให้คีย์ลัดดั้งเดิมของมันชนกับของ Omega-Fire:

- ลูกศร ↑↓: นำทางในล็อก (คีย์ลัดดั้งเดิมของ `lnav` ส่งต่อตามเดิม)
- ลูกศร ←→: เลื่อนแนวนอนบนบรรทัดยาว (คีย์ลัดดั้งเดิมของ `lnav`)
- `g` / `G`: ไปที่ต้น / ท้าย (คีย์ลัดดั้งเดิมของ `lnav`)
- `Ctrl+C`: ทำเครื่องหมายบรรทัดปัจจุบันและคัดลอกไปยังคลิปบอร์ดของระบบ (แทนคำสั่งคัดลอกดั้งเดิมของ `lnav` ซึ่งอาจค้างในบางระบบ)
- `t` ตัวเล็ก: ธีมถัดไป เฉพาะมุมมองนี้ (`T` ตัวใหญ่ยังคงเป็นคีย์ลัดดั้งเดิมของ `lnav` สำหรับแสดงเวลาที่ผ่านไประหว่างบรรทัด)
- `Ctrl+Q`: กลับไปยัง Omega-Fire (ปิด `lnav` อย่างเรียบร้อยโดยไม่ออกจากแอปพลิเคชัน)

## ธีมและเทอร์มินัล

ธีม `omega-*` สิบแบบใช้ร่วมกับส่วนอื่นของชุด OMEGA:

```text
omega-base       omega-dark       omega-light
omega-neon       omega-burn       omega-pink
omega-hack       omega-contrast   omega-mono
omega-minimal
```

- สลับธีมด้วย `t` หรือเลือกธีมโดยตรงจากการตั้งค่า (`s`)
- ธีมที่เลือกจะถูกจำไว้และใช้อีกครั้งในการเปิดใช้ครั้งถัดไป
- Omega-Fire ปรับความซับซ้อนทางภาพ (เส้นขอบ, splash, ความหนาแน่นของข้อมูล) ให้เข้ากับเทอร์มินัลที่ตรวจพบโดยอัตโนมัติผ่าน **โปรไฟล์การแสดงผล**: เต็ม, มาตรฐาน, ลดทอน หรือ Mono (ASCII เท่านั้น) โปรไฟล์สามารถกำหนดเองได้จากการตั้งค่า

| ขนาดขั้นต่ำ | โปรไฟล์ | เทอร์มินัลทั่วไป |
|---|---|---|
| 120×32 ขึ้นไป | เต็ม | Ghostty, Alacritty, WezTerm, Kitty |
| 100×28 ขึ้นไป | มาตรฐาน | Konsole, GNOME Terminal, Terminator, xfce4-terminal |
| 80×24 ขึ้นไป | ลดทอน | urxvt, xterm, SSH รุ่นใหม่ |
| ต่ำกว่า 80×24 | Mono (ASCII เท่านั้น) | Linux TTY, SSH รุ่นเก่า |

ต่ำกว่า 80×24 การเปิดใช้งานจะถูกปฏิเสธ (ต้องมีขนาดขั้นต่ำ) ให้ปรับขนาดเทอร์มินัลแล้วเปิดใหม่ หรือใช้ `r` หลังปรับขนาดหากการแสดงผลไม่อัปเดตเอง

## การกำหนดค่า

การกำหนดค่าเฉพาะสามารถปรับได้ใน:

```text
omega-fire/config/omega-fire.conf
```

โดยสามารถกำหนดได้ เช่น:

- พาธของล็อก;
- เซิร์ฟเวอร์และแหล่งสำหรับการมอนิเตอร์;
- แบ็กเอนด์ที่มีหรือพาธที่กำหนดเอง;
- สภาพแวดล้อมที่จะวิเคราะห์;
- พารามิเตอร์ที่ปรับให้เหมาะกับการติดตั้งเฉพาะ

การกำหนดค่าจะถูกอ่านใหม่เมื่อเริ่มใหม่หรือเมื่อสแกนใหม่ด้วยตนเอง (เมนู 1.3 หรือ 7.4)

ไฟล์นี้เป็นทางเลือกทั้งหมด (แอปพลิเคชันทำงานได้ตามปกติโดยไม่มีไฟล์นี้ โดยใช้ตัวแปรสภาพแวดล้อมแทน) และ **ไม่รวมอยู่ในไฟล์แจกจ่าย** — การอัปเดตจะไม่เขียนทับไฟล์นี้อย่างเงียบ ๆ และ `install.sh` จะกู้คืนไฟล์นี้เองโดยอัตโนมัติจากการติดตั้งเดิมหากมี (ดู « การอัปเดต » ด้านบน)

### พาธภายในและพาธของระบบ

โดยค่าเริ่มต้น Omega-Fire ทำงานในโฟลเดอร์ของตัวเอง:

```text
var/exports/       # โฟลเดอร์ภายในโปรเจกต์
/var/exports/      # พาธสัมบูรณ์ของระบบ
```

ดังนั้น `/` ตัวแรกจึงมีความหมาย การนำเข้าและส่งออกไปยังระบบต้องได้รับการร้องขออย่างชัดเจนจากผู้ใช้

## แบ็กเอนด์และความเข้ากันได้

Omega-Fire ตรวจหาส่วนประกอบและเปิดใช้เฉพาะฟีเจอร์ที่ใช้งานได้

| ส่วนประกอบ | บทบาท | สถานะ |
|---|---|---|
| nftables | ไฟร์วอลล์ IPv4/IPv6 สมัยใหม่ | แนะนำ |
| iptables | ไฟร์วอลล์ IPv4 | เข้ากันได้ |
| ip6tables | ไฟร์วอลล์ IPv6 กับ iptables | เข้ากันได้หากมี |
| Fail2Ban | jail และการแบนอัตโนมัติ | ทางเลือก |
| conntrack | การเชื่อมต่อที่ใช้งานอยู่ | ทางเลือก |
| lnav | การวิเคราะห์ล็อกขั้นสูง | ทางเลือก |
| systemd, runit, OpenRC | การจัดการบริการ | ตรวจหาอัตโนมัติ |
| Docker, VNC, เซิร์ฟเวอร์ | แอปพลิเคชันและบริการที่ตรวจพบ | ขึ้นกับการติดตั้ง |

### IPv4 และ IPv6

ทั้งสองตระกูลที่อยู่ได้รับการรองรับโดยแบ็กเอนด์ที่เข้ากันได้:

- nftables: IPv4 และ IPv6 แบบ dual stack;
- iptables/ip6tables: ขึ้นกับไบนารีที่มี;
- Fail2Ban: ขึ้นกับการกำหนดค่าของ jail และระบบ

รูปแบบ IPv6 แบบยาว บีบอัด ภายใน ผสม มีเลขศูนย์ และในรูปแบบ CIDR จะได้รับการจัดการโดยส่วนประกอบที่เกี่ยวข้อง

## การจัดเก็บถาวร ล็อก และการส่งออก

### การจัดเก็บถาวร

- SQLite ผ่าน `sqlite3`
- ตารางเกี่ยวกับการแบน กฎ การตรวจสอบ และ snapshot
- migration ที่มีเวอร์ชันและนำไปใช้โดยอัตโนมัติ
- ไฟล์เก็บถาวรสถานะทั้งหมดในรูปแบบ `.tar.gz`
- รายการปักหมุด (แหล่งล็อกโปรด) และประวัติล่าสุดถูกเก็บเป็น JSON (`var/runtime/`) และคงอยู่หลังเริ่มใหม่

### ล็อก

- ล็อกข้อความของแอปพลิเคชัน: `var/logs/app.log`
- ล็อกการตรวจสอบ JSON แบบมีโครงสร้าง ประกอบด้วย `event_type`, `actor`, `action`, `result` และ `details`

### การส่งออก

การส่งออกมีให้ใช้ในรูปแบบ JSON, TXT และ HTML พร้อมธีม CSS หลายแบบสำหรับรายงาน HTML

## ความปลอดภัย

Omega-Fire ทำงานกับส่วนประกอบสำคัญของระบบ จึงต้องใช้งานอย่างระมัดระวัง

- การเปิดใช้งานต้องใช้สิทธิ์ root ผ่าน `sudo`
- flush การล้างทั้งหมด และการใช้นโยบายอาจทำลายข้อมูลได้
- นโยบายที่กำหนดไว้ล่วงหน้าจะสั่งสำรองข้อมูลอัตโนมัติก่อนแก้ไข
- สำรองข้อมูลด้วยตนเองก่อนการเปลี่ยนแปลงสำคัญแต่ละครั้ง
- ตรวจสอบสถานะจริงของไฟร์วอลล์ jail และการเชื่อมต่อหลังการทำงานแต่ละครั้ง
- ทดสอบบนเครื่องหรือเป้าหมายที่ใช้แล้วทิ้งก่อน
- ใช้เครือข่ายสำหรับเอกสาร RFC 5737 ในการทดสอบ IPv4: `192.0.2.0/24`, `198.51.100.0/24` และ `203.0.113.0/24`
- ตรวจสอบไฟล์ส่งออกและ snapshot ก่อนกู้คืนบนเครื่องที่ใช้งานจริง
- อย่าให้สิทธิ์กับโฟลเดอร์ `var/` กว้างเกินความจำเป็น

## การทดสอบและคุณภาพ

โปรเจกต์มีชุดทดสอบหน่วยดั้งเดิม 152 รายการ ซึ่งเขียนก่อนการย้ายไปใช้ Textual: ครอบคลุมโดเมนธุรกิจ การประสานงาน (`application/`) โครงสร้างพื้นฐาน และอินเทอร์เฟซ Rich (`interfaces/cli/`) แต่ **ยังไม่ครอบคลุม `interfaces/tui/`** (อินเทอร์เฟซ Textual เริ่มต้น) ไฟล์เก็บถาวรนี้ไม่มีโฟลเดอร์ `tests/`: ดึงจากที่เก็บสำหรับการพัฒนาของคุณหากต้องการรัน

```bash
source .venv/bin/activate
python -m unittest discover tests/unit -v
```

เนื่องจากสถาปัตยกรรมแบบชั้นแยกโดเมนธุรกิจออกจากส่วนนำเสนออย่างเคร่งครัด (`domain/`, `application/`, `ports/` เป็น `Protocol` ดู [สถาปัตยกรรม](#สถาปัตยกรรม)) ชุดทดสอบนี้จึงยังใช้ได้โดยไม่ต้องเปลี่ยนแม้จะย้ายแล้ว: มีเพียงอินเทอร์เฟซ Textual ที่ใหม่กว่าเท่านั้นที่ยังไม่มีการทดสอบครอบคลุมของตัวเอง

หากคุณมีส่วนร่วมพัฒนาโปรเจกต์ ให้ติดตั้งเครื่องมือด้านคุณภาพที่ระบุไว้ (เป็นคอมเมนต์) ใน `requirements.txt`:

```bash
pip install pytest pytest-cov black flake8 mypy
```

เครื่องมือที่ใช้ได้เมื่อติดตั้งแล้ว:

```bash
black .
flake8 .
mypy src/
pytest --cov
```

## สถานะของโปรเจกต์

### ส่วนที่ใช้งานได้

- TUI Textual แบบรวมศูนย์สำหรับกลไกความปลอดภัยเครือข่ายหลัก แบบฟอร์มที่ผ่านการตรวจสอบ ธีม และความช่วยเหลือตามบริบทที่ใช้ร่วมกับชุด OMEGA
- อินเทอร์เฟซ Rich ดั้งเดิมถูกเก็บไว้เป็นทางสำรอง (`--legacy-cli`)
- ตรวจหาความสามารถโดยอัตโนมัติ
- จัดการแบ็กเอนด์ที่มี
- รองรับ IPv4/IPv6 ตามเครื่องมือที่มี
- การบันทึกล็อกของแอปพลิเคชันและการตรวจสอบ
- การสำรองและกู้คืน
- การส่งออก JSON, TXT และ HTML
- แดชบอร์ดและสถิติที่รีเฟรชในเบื้องหลังโดยไม่บล็อกอินเทอร์เฟซ
- สถาปัตยกรรมแบบชั้นที่มีเอกสารประกอบ

### ข้อจำกัดที่ทราบ

- ชุดทดสอบ (152) ยังไม่ครอบคลุมอินเทอร์เฟซ Textual (`interfaces/tui/`) ซึ่งเขียนขึ้นหลังจากนั้น (ดู [การทดสอบและคุณภาพ](#การทดสอบและคุณภาพ))
- กลไก `ExecutionPlan`/`PipelineStep` ยังคงอยู่บางส่วนในโปรเจกต์
- ความพร้อมใช้งานของฟีเจอร์ที่แน่นอนขึ้นกับไบนารี บริการ สิทธิ์ และการกำหนดค่าของเครื่องโฮสต์
- อินเทอร์เฟซ Rich ดั้งเดิม (`--legacy-cli`) ไม่ใช่แกนหลักของการพัฒนาอีกต่อไป แต่ยังถูกเก็บไว้จนกว่าอินเทอร์เฟซ Textual จะเชื่อถือได้เต็มที่ในสภาพการใช้งานจริง

## การถอนการติดตั้ง

หากข้อมูลยังอยู่ในโฟลเดอร์ของโปรเจกต์:

```bash
sudo rm -rf ~/omega-fire
```

ลบไฟล์ที่ส่งออกไว้ที่อื่น alias `fire` ที่อาจเพิ่มไว้ใน `~/.bashrc` หรือ `~/.zshrc` และกลุ่มเฉพาะหากไม่ใช้แล้วด้วยตนเอง:

```bash
sudo groupdel omega-fire
```

รันคำสั่งสุดท้ายนี้เฉพาะเมื่อไม่มีไฟล์หรือบริการอื่นใดพึ่งพากลุ่มนี้
