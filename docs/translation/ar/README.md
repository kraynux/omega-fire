**Omega-Fire** تطبيق TUI (واجهة مستخدم طرفية) بلغة Python مبني باستخدام [Textual](https://github.com/Textualize/textual). يوفّر من الطرفية واجهة واحدة لإدارة الجدران النارية في Linux، وFail2Ban، والعناوين المحظورة، وقواعد الشبكة، والسجلات، وإحصاءات النظام.

واجهة Textual هي وضع التشغيل الافتراضي، ويتم التنقل فيها عبر القوائم، والنماذج المتحقَّق منها (تُفحص جميع الحقول المطلوبة قبل المتابعة)، والشاشات المخصصة، مع سمات ومساعدة سياقية واختصارات لوحة مفاتيح مشتركة مع بقية مجموعة OMEGA (omega-check، omega-deep، omega-stress...). وتبقى واجهة [Rich](https://github.com/Textualize/rich) القديمة، التسلسلية التي تُدار بإدخال الأرقام، متاحة عبر `--legacy-cli` (انظر [التشغيل](#التشغيل)). 
معاينة: [لقطات الشاشة](https://kraynux.snake-mackarel.ts.net/omega-fire/screenshots/index-2.html)

## التقديم

يعمل Omega-Fire بوصفه **مركز قيادة محليًا** لأمان الشبكة. يكتشف تلقائيًا المكونات الموجودة على الجهاز ويكيّف القوائم مع القدرات المتاحة فعلًا.

### الأهداف

- جمع nftables وiptables وip6tables وFail2Ban في واجهة متسقة.
- تسهيل مراقبة الاتصالات والحظر وأحداث النظام والتصرف بشأنها.
- مركزة التصدير والنسخ الاحتياطي والتدقيق وسجل العمليات.
- الحفاظ على بنية قابلة للاختبار والتوسيع.
- العمل في وضع محدود عند غياب مكوّن اختياري.

### ما يفعله Omega-Fire

- يكتشف الخوادم الخلفية والخدمات والنواة والأدوات المتاحة.
- يدير nftables وiptables وip6tables عند وجود هذه المكونات.
- يدير عناوين IP المحظورة، فرادى أو دفعات، مع الاستيراد والتصدير والمزامنة والتفريغ (flush).
- ينشئ القواعد المتقدمة ويسردها ويحذفها.
- يطبّق سياسات معرّفة مسبقًا مع نسخ احتياطي تلقائي مسبق.
- يدير jails في Fail2Ban وحالات الحظر فيها.
- يحلّل السجلات مباشرة أو في صورة إحصاءات.
- يوفّر المراقبة في صورة monitoring.
- يستخدم conntrack لعرض الاتصالات النشطة عند توفره.
- ينتج تصديرات JSON وTXT وHTML.
- ينسخ الحالة الكاملة احتياطيًا ويستعيدها في أرشيفات `.tar.gz`.
- يسجّل العمليات في سجل التطبيق وفي تدقيق JSON منظَّم.
- يراقب الخدمات والتطبيقات المكتشفة: systemd وrunit وOpenRC وDocker والخوادم وVNC وغيرها.

### ما لا يفعله المشروع

- لا يحل محل nftables أو iptables أو Fail2Ban.
- ليس جدارًا ناريًا مستقلًا عن النظام.
- لا يوفّر مصادقة متعددة المستخدمين.
- لا يكشف واجهة API شبكية أثناء التشغيل العادي.
- ليس لوحة معلومات ويب.
- لا يحمي جهازًا بعيدًا مباشرة من جهاز آخر.
- لا يثبّت افتراضيًا أي ملف خارج مجلده الخاص.
- لا يضمن توفر جميع الخوادم الخلفية في جميع التوزيعات.

## الوظائف

### 1. القدرات والتشخيص

- عرض سجل القدرات المكتشفة.
- الاطلاع التفصيلي على قدرة ما حسب معرّفها.
- إعادة فحص النظام يدويًا بعد تثبيت مكوّن.
- الاطلاع على التشخيصات الأخيرة.
- الاطلاع على سجل التطبيق والبحث فيه.
- تصدير الحالة والتشخيصات بصيغة JSON أو TXT أو HTML.
- فئة **حزمة omega**: omega-serv (النسخ المكتشفة والعاملة)، وomega-waf (الإضافة `magnet` مفعّلة)، وomega-jail (الـ jails المثبتة)، تظهر في السجل ولوحة المعلومات والتقارير.

### 2. الإدارة الموحّدة لعناوين IP

تتيح القائمة السوداء الموحّدة العمل مع nftables وiptables من الشاشة نفسها.

- حظر عنوان IP أو قائمة عناوين.
- رفع الحظر فرادى أو دفعات.
- الإدخال المباشر أو الاستيراد من ملف.
- قائمة حسب الخادم الخلفي أو عرض موحّد.
- المزامنة بين الخادمين الخلفيين NFTables/IPTables.
- تصدير القوائم وإعادة استيرادها.
- تنظيف كامل لخادم خلفي واحد أو أكثر.
- دعم IPv4 وIPv6.
- إدارة ملفات قائمة الحظر (`var/blocklist/`) وتثبيتاتها مباشرة من الشاشة المخصصة؛ والملفات المقترحة افتراضيًا، `blocklist.txt` و`blocklist-f2b.txt`، تُنشأ فارغة عند التشغيل الأول.

### 3. إدارة القواعد والسياسات

- معالج خطوة بخطوة لإنشاء قاعدة متقدمة.
- قائمة بقواعد النظام والقواعد التي أنشأها Omega-Fire.
- حذف قاعدة بالتحديد.
- تنظيف تلقائي للقواعد غير النشطة في قاعدة المرجع.
- تنظيف قاعدة البيانات وإعادة مزامنتها مع الجدار الناري الفعلي، مع معاينة ونسخة احتياطية مسبقة، دون تعديل الجدار الناري نفسه أبدًا.
- قواعد الأدوات الأخرى (UFW وTailscale وDocker…) تُعرَّف بأصلها: تُعرض للعلم فقط، ولا تُحذف أبدًا من Omega-Fire.
- حماية قبل تطبيق سياسة أو تفريغ iptables حين تكون لأدوات أخرى قواعد فيه: التطبيق في كل مكان، أو على nftables فقط، أو الإلغاء — العواقب مفصّلة في المساعدة.
- تطبيق سياسات معرّفة مسبقًا.
- نسخ احتياطي تلقائي قبل تطبيق سياسة.
- تخصيص سياسة وحفظها واستعادتها.
- إظهار السياسة النشطة في قائمة الحالة ولوحة المعلومات.
- الإشارة إلى ملفات التعريف المعدّلة بالصيغة `ملف التعريف + CUSTOM`.
- إدارة الجداول (القائمة 3.5): تشخيص للقراءة فقط لكل واجهة خلفية (وجود الجدول، وسياسات input/output/forward، وعدد القواعد) مع شرح السياسات المختلفة بين الواجهات الخلفية (الأثر الفعلي، والسبب، والعلاج).
- تهيئة جدول nftables عند الاستخدام الأول، دون الكتابة فوق chain مهيأة مسبقًا أبدًا.
- إعادة سياسات chain إلى ACCEPT على خادم خلفي، لتصحيح سياسة مقيِّدة يتيمة تركها ملف تعريف سابق.
- تفريغ موجّه لخادم خلفي واحد أو تفريغ متزامن لجميع الخوادم الخلفية المكتشفة في إجراء واحد.
- حذف كامل لجدول nftables (إجراء متقدم، يتجاوز القواعد وحدها).

### 4. إدارة Fail2Ban

- حالة تفصيلية للـ jails ومعاملاتها.
- عدد عناوين IP المحظورة ومعلومات rate-limit.
- البحث عن عنوان IP في الـ jails.
- ban وunban فرديان أو متعددان.
- نقل عناوين IP بين الـ jails والخوادم الخلفية والملفات.
- إنشاء موجَّه لـ jail مخصص.
- قوالب jails معرّفة مسبقًا، قابلة للتعديل والحذف.
- أصل كل jail: Omega-Fire، أو omega-jail، أو الإعداد الرئيسي لـ fail2ban، أو ملف آخر.
- حذف موثوق لأي jail مهما كان اسم ملفه: تحذير لـ jail ثبّته omega-jail، ورفض مع شرح لـ jail من `jail.local` أو من ملف مشترك، ولا تُحذف المرشحات القياسية لـ fail2ban أبدًا.
- تفريغ jail أو تنظيف عام.
- التصدير بصيغة JSON أو TXT أو HTML.
- التحقق من التهيئة وتدقيقها.
- التحكم في الخدمة: الحالة، والتشغيل، والإيقاف، وإعادة التشغيل، والتفعيل والتعطيل عند الإقلاع؛ وبعد التشغيل أو الإيقاف يُحدَّث سجل القدرات ولوحة المعلومات.

### 5. السجلات والصيانة

- **مكتبة السجلات** (5.1): استيراد تلقائي لسجلات نسخ omega-serv المكتشفة، ومنها سجلات omega-waf، وتثبيت مسار يدويًا، وجلب سجل بعيد عبر SSH (مفتاح أو وكيل، ولا كلمة مرور أبدًا).
- **المفضلات** (5.2): الجمع بين سجلات من المكتبة، وحفظها باسم مع عارض، وتشغيلها مباشرة.
- **عرض السجلات** (5.3): سجل واحد دون إعداد، بالعارض الذي تختاره — بسيط (لوحة معلومات في الوقت الحقيقي: حالات HTTP ومنها الرفض 403 و429، وTop 5 IP، والمسارات المطلوبة ومسارات 404، مثل omega-log)، أو كلاسيكي (آخر الأسطر ثم المتابعة المباشرة)، أو `lnav`.
- **المكتبة تغذّي كل اختيارات السجلات**: تعرضها 5.4 و5.5 و5.6، وكذلك 8.5 و8.6، في أعلى القائمة، قبل العناصر المثبَّتة.
- تكامل `lnav`: عدة سجلات مدمجة في عرض زمني واحد، مغلّف بترويسة/تذييل Omega-Fire (انظر [التنقل](#التنقل)).
- تحليل عناوين IP الأكثر تكرارًا باستخدام Top N (5.4)، قابل للتصدير لإعادة تحميله في التنظيف الموجّه؛ والبحث عن عنوان IP محدد في الملف كاملًا وإزالة العنوان المختار مباشرة، دون تجميد الواجهة.
- تنظيف موجّه لعنوان IP واحد أو أكثر في ملفات LOG أو TXT، تُكتب يدويًا أو تُحدَّد من تصدير.
- ملفات مثبتة مع **إعدادات مسبقة قابلة للتحديد**: لا تُقترح إلا المسارات المعتادة الموجودة فعلًا على الجهاز.
- التدوير والنسخ الاحتياطي الفوري أو المجدول، **المنفَّذ فعليًا كل ليلة** (مؤقّت systemd يعمل بصلاحيات root، وإلا فسطر في crontab الخاص بـ root)، مع عدد النسخ الاحتياطية المحفوظة، وآخر نسخة احتياطية والتالية.
- استعادة نسخة احتياطية.
- الحذف حسب القِدم أو الحصة أو النوع أو الاختيار اليدوي.
- تنظيف متقدم حسب المجلد أو البيئة.
- إحصاءات على مدى 24 ساعة أو 7 أيام أو 30 يومًا (5.10، عرض سريع).
- تحليل الأحداث والتحركات والحصص وعناوين IP الموجودة في الـ jails.

### 6. التصدير والتقارير

الصيغ المتاحة:

- **JSON**: بيانات منظّمة وقابلة لإعادة الاستخدام.
- **TXT**: صيغة خام أو مهيأة للحقن.
- **HTML**: تقرير مقروء ومرئي.

التقارير المتاحة:

- القائمة السوداء الكاملة.
- ruleset منظَّم.
- قواعد مختارة حسب المصدر: النظام أو Omega-Fire أو النشطة.
- تقرير تدقيق كامل.
- إحصاءات Fail2Ban.
- حالة النظام وتشخيصاته.
- تقارير إحصائية على مدى 7 أو 30 يومًا.
- ترتيب Top N لعناوين IP.
- **إحصاءات السجلات** (6.5): التقرير نفسه المستخدم في omega-serv وomega-log (الملخص، حالات HTTP، أعلى عناوين IP، المسارات المطلوبة، مسارات 404، التوزيع حسب الساعة، الاتجاه اليومي)، للسجلات فقط؛ ويبقى الحظر وحالة جدار الحماية في تقارير 7 و30 يومًا.
- دليل المساعدة والأسئلة الشائعة.

**عرض كل التصديرات** (6.6): كل الملفات المصدَّرة في مكان واحد، مع النوع والتاريخ والحجم؛ يُفتح تقرير HTML في متصفح الويب الافتراضي للمستخدم، ويُقرأ ملف JSON أو TXT داخل Omega-Fire، دون طرفية ولا مدير ملفات.

سمات HTML:

- `omega-base` — أزرق ليلي وسماوي، السمة الافتراضية.
- `omega-burn` — جمر أحمر برتقالي.
- `omega-neon` — سايبربانك سماوي وأرجواني.
- `light-basic` — فاتح وبسيط.
- `light-alt` — ورق كريمي وأخضر غابي.

لغة التصدير: تُضبط على حدة في الإعدادات (القيمة الافتراضية « مثل الواجهة »)، لتسليم تقرير بلغة قارئه دون تغيير لغة الواجهة.

### 7. النظام والاستمرارية

- نسخ احتياطي للحالة الكاملة: القواعد، وحظر nftables، وحظر iptables، وFail2Ban.
- إنشاء أرشيفات `.tar.gz` مؤرخة.
- سرد اللقطات واستعادتها: لا تُعاد إلا قواعد Omega-Fire القابلة لإعادة الإنشاء بشكل مطابق؛ ولا تُمسّ قواعد الأدوات الأخرى أبدًا.
- سجل الإجراءات.
- تصفية السجل وحذفه.
- إعادة تحميل التهيئة وإعادة الفحص دون إعادة تشغيل.

### 8. المراقبة والإحصاءات

- لوحة معلومات في الوقت الفعلي بتحديث دوري (كل ثانيتين)، دون حجب الواجهة أثناء جمع البيانات.
- عرض السياسة النشطة.
- الاتصالات النشطة عبر conntrack.
- الحركة، والأحداث، والإحصاءات، وسجلات الخادم.
- تقارير مجمّعة على مدى 7 و30 يومًا.
- تصدير HTML للقطات والتقارير.

### 9. الإعدادات

- اختيار السمة النشطة من بين السمات العشر `omega-*` المشتركة مع بقية المجموعة (انظر [السمات والطرفيات](#السمات-والطرفيات))، وهي محفوظة بين تشغيلين.
- تجاوز يدوي لملف العرض (تلقائي، أو كامل، أو قياسي، أو مختصر، أو mono فقط)، يُطبَّق في التشغيل التالي.
- لغة الواجهة من بين 17 لغة (انظر [لغات الواجهة](#لغات-الواجهة)): تُعاد تشغيل الواجهة وحدها، ولا تُمسّ قواعد الجدار الناري ولا Fail2Ban ولا الخدمات.
- لغة تصدير HTML وTXT، مستقلة عن لغة الواجهة.
- مجلدات التصدير ولقطات الشاشة قابلة للتعديل، مع إفراغها بعد التأكيد.
- متاح من القائمة الرئيسية (`9. الإعدادات`) أو مباشرة بالمفتاح `s`.

### 10. مساعدة

- **دليل المساعدة**: كل صفحات المساعدة مجمّعة بترتيب القوائم، وكل صفحة تفتح الصفحات المرتبطة بها.
- **الأسئلة الشائعة**: الأسئلة الفعلية التي ظهرت أثناء الاستخدام (قواعد الأدوات الأخرى، والاستعادة، وFail2Ban، والسجلات، والتصديرات والمتصفح).
- تصدير الدليل والأسئلة الشائعة بصيغة HTML، بلغة التصديرات.
- يبقى المفتاح `a` مساعدة الشاشة الحالية.

## البنية

```text
src/omega_fire/
├── app/              التمهيد وحاوية حقن الاعتماديات
├── core/             القدرات، والتعدادات، والاستثناءات
├── domain/           منطق أعمال خالص: القواعد، وIP، وjails، والسجلات
├── application/      التنسيق: commands وqueries
├── infrastructure/   الخوادم الخلفية، والتخزين، والتصدير، والسجلات، ومجسات النظام
├── ports/            عقود Protocol/ABC
├── interfaces/       interfaces/tui/ (Textual، افتراضي) + interfaces/cli/ (Rich، --legacy-cli)
├── plugins/          إضافات مدمجة: nftables، iptables، Fail2Ban، conntrack
└── shared/           التحليل، والشبكة، والتنسيق، وأدوات مشتركة
```

### مبادئ التصميم

- لا يحتوي `domain/` على أي إدخال/إخراج ولا أي اعتماد على البنية التحتية.
- ينسّق `application/` حالات الاستخدام عبر المجال والمنافذ — تستدعي شاشات Textual وإجراءات واجهة Rich الـ commands/queries نفسها، ولا يعتمد منطق الأعمال على أي من الواجهتين.
- `infrastructure/` هي الطبقة الوحيدة المسموح لها باستدعاء `nft` و`iptables` و`fail2ban-client` وغيرها من الأدوات الخارجية (subprocess، pty، الملفات).
- يجب ألا يستدعي `interfaces/` الأداة `subprocess` مباشرة.
- يعرّف `ports/` العقود التي تتوقعها المحوّلات.
- يوفّر `core/` سجل القدرات الذي تستخدمه الطبقات المختلفة.
- تتيح الإضافات إضافة خوادم خلفية أو تطويرها دون تعديل مجال الأعمال.
- تعتمد واجهة Textual (`interfaces/tui/`) على [`omega-lib`](https://github.com/) (اعتمادية مشتركة لمجموعة OMEGA كلها: سمة من 9 رموز، واكتشاف الطرفية، وعقود منافذ مشتركة)، وهي غير منشورة على PyPI — ومضمّنة في الأرشيف الموزَّع (`vendor/omega-lib/`، انظر [التثبيت](#التثبيت)).
- كل استدعاء قد يكون بطيئًا (خادم الجدار الناري الخلفي، `fail2ban-client`، القرص) يُطلق من شاشة Textual يُنفَّذ في الخلفية (خيط)، وليس أبدًا على الخيط الرئيسي للواجهة — فتبقى لوحة المعلومات أو النموذج مستجيبين أثناء العملية بدلًا من تجميد التطبيق كله.

### بنية البيانات

يستخدم Omega-Fire قاعدة SQLite عبر المكتبة القياسية `sqlite3`، دون ORM خارجي. وتتعلق مجموعات البيانات الرئيسية بالحظر، والقواعد، وأحداث التدقيق، واللقطات.

عمليات الترحيل ذات إصدارات وتُطبَّق تلقائيًا عند البدء.

## المتطلبات المسبقة

### النظام

- Linux، وفي المقام الأول Arch Linux والتوزيعات المتوافقة.
- Python 3.10 أو أحدث.
- صلاحيات root متاحة عبر `sudo`.
- مدير خدمات: systemd أو runit أو OpenRC.

### اعتماديات Python

اعتماديات الإنتاج معرّفة في `requirements.txt`:

- `textual` — واجهة TUI الافتراضية.
- `omega-lib` — السمة، واكتشاف الطرفية، والعقود المشتركة مع مجموعة OMEGA (غير منشورة على PyPI، انظر [البنية](#البنية) و[التثبيت](#التثبيت)).
- `rich` — عرض واجهة `--legacy-cli` وبعض التقارير.

- `pyte` — محاكي طرفية افتراضي، لتغليف `lnav` (القائمة 8.6 وعارض lnav في 5.2 / 5.3).

أدوات الجودة (`pytest` و`black` و`flake8` و`mypy`) مذكورة كتعليق في `requirements.txt`: أزل التعليق عنها أو ثبّتها بشكل منفصل إذا كنت تساهم في المشروع (انظر [الاختبارات والجودة](#الاختبارات-والجودة)).

يعمل التطبيق في وضع محدود إذا غابت هذه الأدوات:

- `fail2ban` — الحظر المؤتمت.

### الطريقة 3 — تثبيت مفصّل

```bash
# 0. التحقق من عدم إعادة التشغيل من داخل omega-fire موجود
[ "$(basename "$PWD")" = "omega-fire" ] && { echo "❌ يبدو أنك داخل مجلد omega-fire بالفعل — انظر قسم التحديث في README." >&2; exit 1; }

# 1. الاستخراج
[ -d omega-fire ] && echo "ℹ️ مستخرج هنا مسبقًا، تم تخطي هذه الخطوة." || tar -xzf omega-fire.tar.gz

# 2. النقل إلى المجلد الرئيسي
[ -d ~/omega-fire ] && echo "ℹ️ ~/omega-fire موجود مسبقًا، تم تخطي النقل." || mv omega-fire ~/

# 3. الدخول إلى المشروع
cd ~/omega-fire/

# 4. إنشاء البيئة الافتراضية
[ -d .venv ] && echo "ℹ️ .venv موجود مسبقًا، تم تخطي الإنشاء." || python3 -m venv .venv

# 5. تثبيت الاعتماديات (omega-lib المضمّنة، إن وُجدت، قبل requirements.txt)
source .venv/bin/activate
[ -d vendor/omega-lib ] && pip install -q -e vendor/omega-lib
pip install -r requirements.txt

# 6. جعل المشغّل قابلًا للتنفيذ
chmod +x omega-fire.sh

# 7. تحضير var/ لـ root والمستخدم الحالي
mkdir -p var
getent group omega-fire >/dev/null 2>&1 || sudo groupadd omega-fire
groups "$USER" 2>/dev/null | grep -qw omega-fire || sudo usermod -aG omega-fire "$USER"
sudo chgrp -R omega-fire var
sudo chmod -R 2775 var

# 8. التشغيل
./omega-fire.sh
```

لا يوجد `vendor/omega-lib/` إلا في الأرشيف الرسمي (يضمّنه `build-release.sh` تلقائيًا، لأن omega-lib غير منشورة على PyPI)؛ وفي نسخة تطوير مستنسخة، ثبّتها بشكل منفصل من مستودعها الخاص (`pip install -e path/to/omega-lib`).

تتيح المجموعة المخصصة وبت `setgid` لـ root والمستخدم مشاركة الملفات المنتجة في `var/` دون فتح الأذونات للنظام كله. وقد يلزم تسجيل دخول جديد أو `newgrp omega-fire` للاستفادة فورًا من الانتماء إلى المجموعة.

### التحديث

إذا كان `~/omega-fire` موجودًا مسبقًا (تثبيت سابق)، **فلا تُعد تشغيل أوامر التثبيت أبدًا من داخل هذا المجلد**: سيحاول `tar` إنشاء `omega-fire/omega-fire/` متداخل وسيفشل، عادةً مع سلسلة من أخطاء « الإذن مرفوض » إذا كان المجلد مملوكًا لـ `root` (وهذا شائع إذا جرى استخراج سابق بالخطأ باستخدام `sudo tar`).

الإجراء الموصى به، من أي مجلد **غير `~/omega-fire`** (عادةً `~` نفسه):

```bash
# 1. التحقق من حالة التثبيت الموجود ومالكه
ls -ld ~/omega-fire

# 2. وضع التثبيت القديم جانبًا بدلًا من الكتابة فوقه
sudo mv ~/omega-fire ~/omega-fire.old-$(date +%Y%m%d)

# 3. استخراج الأرشيف الجديد مباشرة في المجلد الرئيسي
tar -xzf omega-fire.tar.gz -C ~/

# 4. إعادة التثبيت (يعيد إنشاء venv، ويعيد تثبيت الاعتماديات، ويعيد ضبط أذونات var/)
cd ~/omega-fire
chmod +x install.sh
./install.sh

# 5. التشغيل
./omega-fire.sh
```

تكتشف الخطوة 4 (`./install.sh`) هذه الحالة تلقائيًا (قاعدة البيانات `var/db/` غائبة هنا، ومجلد `~/omega-fire.old-YYYYMMDD` موجود بجوارها مباشرة) و**تسترجع بنفسها** `config/omega-fire.conf` وقاعدة البيانات وقائمة الحظر والنسخ الاحتياطية والتصديرات ولقطات الشاشة من التثبيت القديم — دون أي سؤال ودون أي خطوة يدوية. لا شيء آخر يلزم فعله غير النقاط من 1 إلى 5 أعلاه، أيًا كان محتوى تثبيتك السابق.

إذا وُجدت بجواره عدة مجلدات تشبه تثبيتًا قديمًا (التباس)، فإن `install.sh` لا يخمّن شيئًا: يعرض مساراتها ويدعوك إلى تشغيل `sudo ./migrate-state.sh <المجلد>` بنفسك بعد تحديد المصدر الصحيح.

بعد التحقق من صحة التثبيت الجديد، يمكن حذف المجلد القديم `~/omega-fire.old-YYYYMMDD` (`sudo rm -rf ~/omega-fire.old-YYYYMMDD`).

## الاستخدام

### التشغيل

```bash
cd ~/omega-fire
./omega-fire.sh

# أو ببساطة، إذا أُنشئ الاسم المستعار:
fire
```

المشغّل:

1. يتحقق من صلاحيات root ويعيد التشغيل عبر `sudo` عند الحاجة.
2. يكتشف `.venv` أو `venv` أو Python النظام.
3. يضبط `PYTHONPATH` على `src/`.
4. يشغّل `python -m omega_fire` — أي واجهة **Textual** افتراضيًا.

لتشغيل واجهة Rich القديمة (إدخال الأرقام تسلسليًا) بدلًا منها:

```bash
./omega-fire.sh --legacy-cli
```

**لم تعد واجهة Rich القديمة قيد التطوير، لكنها لا تزال متاحة.** تبقى الواجهة القديمة واجهة الإصدار 3.0، بالفرنسية: القائمة 5 الأصلية (دون المكتبة والمفضلات والعارض الكلاسيكي)، ودون «عرض كل التصديرات»، ودون دليل مساعدة ولا أسئلة شائعة، ودون إعدادات مسبقة. أما واجهة Textual فتحمل الإصدار 3.5 كاملًا.

### لغات الواجهة

17 لغة: الفرنسية، الإنجليزية، الإسبانية، البرتغالية (البرازيل)، الإيطالية، الألمانية، الهولندية، البولندية، الروسية، الصينية، الفيتنامية، التايلاندية، الإندونيسية، اليابانية، الكورية، الهندية، العربية. يتم الاختيار من الإعدادات (المفتاح `s`، « Langue / Language »، وهي تسمية لا تُترجم أبدًا)، ويُطبَّق بإعادة تشغيل الواجهة فقط، أو لمرة واحدة عبر `OMEGA_FIRE_LANG=ar ./omega-fire.sh` (يحتفظ بها المشغّل عبر `sudo`). في طرفية النص في Linux ‏(TTY)، تُعرض اللغات التي لا توجد كتابتها في خطوط الطرفية (الفيتنامية، الصينية، التايلاندية، اليابانية، الكورية، الهندية، العربية) بالإنجليزية طوال الجلسة. تُعرض العربية من اليمين إلى اليسار. بالهندية، تعرض Terminator وGNOME Terminal وXfce Terminal وAlacritty النص مصطفًّا، أما الطرفيات التي تركّب الحروف المتصلة بنفسها (Kitty وGhostty وKonsole) فقد تُزيح الإطارات والأعمدة. تُضبط **لغة التصدير** (تقارير HTML وTXT) على حدة، والقيمة الافتراضية « مثل الواجهة ». يبقى سجل التطبيق وسجل التدقيق مسجَّلين بالفرنسية، وتُعرض عناوين السجل باللغة المختارة. تبقى الواجهة القديمة (`--legacy-cli`) بالفرنسية.

### التواصل والدعم

تتيح المساعدة (المفتاح `a`) شاشة **التواصل والدعم**: *ادفع ثمن قهوة* (صفحة PayPal الخاصة بالمطوّر)، و*التواصل مع الدعم* (عنوان البريد الإلكتروني ونموذج التواصل في الموقع، معروضان بوضوح)، و*تسجيلي كمستخدم (مجهول الهوية)* و*التحقق من التحديثات*. التسجيل اختياري، ومعطّل افتراضيًا، ويُرسل مرة واحدة فقط: يُستخدم فقط لإحصاء المستخدمين، وإن رغبت، قارتهم أو بلدهم (قوائم مغلقة، دون أي نص حر). يُرسل مفتاحًا مولَّدًا عشوائيًا واسم البرنامج (`omega-fire`) وإصداره؛ ولا يُرسل أبدًا اسمًا أو اسم جهاز أو إعدادًا أو هدفًا أو نتيجة. لا يُحفظ عنوان IP في التسجيلات، لكنه، كأي زيارة، يمر عبر فحوص الأمان وسجل الخادم المستقبِل. يمكن السحب في أي وقت من الشاشة نفسها (*إلغاء تسجيلي*). يقرأ التحقق من التحديثات قائمة الإصدارات المنشورة على الموقع فقط، ولا يحدث أبدًا دون نقرة.

### المسار العام

1. شاشة البدء (splash)، ثم تحذير إذا كانت الطرفية صغيرة جدًا.
2. اكتشاف قدرات النظام (شاشة مخصصة، غير مانعة).
3. القائمة الرئيسية: 8 أقسام موضوعية (1-8)، والإعدادات (9)، والمساعدة (10).
4. اختيار قسم ثم إجراء — يفتح كل إجراء نموذجًا يُتحقق من جميع حقوله المطلوبة قبل المتابعة.
5. تأكيد صريح قبل أي عملية حساسة أو مدمّرة (تفريغ، أو تنظيف، أو استعادة...).
6. تنفيذ العمليات البطيئة في الخلفية (تبقى الواجهة قابلة للاستخدام أثناء الانتظار)، ثم العودة إلى القائمة مع ملخص للنتيجة.

### التنقل

- السهمان لأعلى/لأسفل: تحريك المؤشر في قائمة.
- Tab / Shift+Tab: التنقل بين حقول النموذج.
- Enter: الاختيار أو التأكيد.
- النقر على صف في جدول: تحديده وملء الحقول المعنية مسبقًا (المصدر المراد تثبيته، والـ jail المستهدف، إلخ).
- `Esc`: العودة إلى الشاشة السابقة (يطلب تأكيد الخروج من الشاشة الرئيسية).
- `a`: مساعدة سياقية — تشرح الإجراء الحالي، أو كل إجراءات القسم الحالي إن لم تُفتح أي شاشة إجراء بعد؛ والدليل الكامل والأسئلة الشائعة في القائمة 10.
- `t`: الانتقال إلى السمة التالية، دون تأكيد.
- `r`: إعادة اكتشاف حجم الطرفية ونوعها.
- `s`: فتح الإعدادات (السمة، وملف العرض، واللغات، والمجلدات).
- `q` / `Ctrl+Q`: الخروج، مع تأكيد.

#### خصوصيات شاشة lnav (8.6، وعارض lnav في 5.2 / 5.3)

يُغلَّف `lnav` داخل طرفية زائفة مع ترويسة/تذييل دائمين لـ Omega-Fire حول عرضه الخاص، لتجنب أي تعارض بين اختصاراته الأصلية واختصارات Omega-Fire:

- السهمان ↑↓: التنقل في السجلات (اختصار أصلي في `lnav`، يُمرَّر كما هو).
- السهمان ←→: التمرير أفقيًا في الأسطر الطويلة (اختصار أصلي في `lnav`).
- `g` / `G`: الانتقال إلى البداية / النهاية (اختصار أصلي في `lnav`).
- `Ctrl+C`: تمييز السطر الحالي ونسخه إلى حافظة النظام (يحل محل أمر النسخ الأصلي في `lnav`، الذي قد يتعطل على بعض الأنظمة).
- `t` صغيرة: السمة التالية، خاصة بهذا العرض (تبقى `T` الكبيرة الاختصار الأصلي في `lnav` لعرض الوقت المنقضي بين الأسطر).
- `Ctrl+Q`: العودة إلى Omega-Fire (يغلق `lnav` بشكل سليم، دون الخروج من التطبيق).

## السمات والطرفيات

عشر سمات `omega-*` مشتركة مع بقية مجموعة OMEGA:

```text
omega-base       omega-dark       omega-light
omega-neon       omega-burn       omega-pink
omega-hack       omega-contrast   omega-mono
omega-minimal
```

- بدّل بين السمات بالمفتاح `t`، أو اختر إحداها مباشرة من الإعدادات (`s`).
- تُحفظ السمة المختارة وتُستعاد في التشغيل التالي.
- يكيّف Omega-Fire تلقائيًا التعقيد المرئي (الحدود، وsplash، وكثافة المعلومات) مع الطرفية المكتشفة عبر **ملف عرض**: كامل، أو قياسي، أو مختصر، أو Mono (ASCII فقط). ويمكن تجاوز ملف العرض يدويًا من الإعدادات.

| الحجم الأدنى | ملف العرض | طرفيات نموذجية |
|---|---|---|
| 120×32 أو أكثر | كامل | Ghostty, Alacritty, WezTerm, Kitty |
| 100×28 أو أكثر | قياسي | Konsole, GNOME Terminal, Terminator, xfce4-terminal |
| 80×24 أو أكثر | مختصر | urxvt، xterm، SSH حديث |
| أقل من 80×24 | Mono (ASCII فقط) | TTY لينكس، SSH قديم |

تحت 80×24، يُرفض التشغيل (الحجم الأدنى مطلوب)؛ غيّر حجم الطرفية ثم أعد التشغيل، أو استخدم `r` بعد تغيير الحجم إذا لم يتحدّث العرض تلقائيًا.

## التهيئة

يمكن ضبط التهيئة الخاصة في:

```text
omega-fire/config/omega-fire.conf
```

ويمكنها أن تحدد خصوصًا:

- مسارات السجلات؛
- خوادم المراقبة ومصادرها؛
- الخوادم الخلفية المتاحة أو المسارات المخصصة؛
- البيئات المراد تحليلها؛
- معاملات مكيّفة لتثبيت معيّن.

تُعاد قراءة التهيئة عند إعادة التشغيل أو أثناء إعادة فحص يدوية (القائمة 1.3 أو 7.4).

هذا الملف اختياري تمامًا (يعمل التطبيق بشكل طبيعي من دونه، بالرجوع إلى متغيرات البيئة) و**مستبعد من الأرشيف الموزَّع** — فلا يكتب أي تحديث فوقه بصمت أبدًا، ويسترجعه `install.sh` بنفسه تلقائيًا من تثبيت قديم إن وُجد (انظر « التحديث » أعلاه).

### المسارات الداخلية ومسارات النظام

افتراضيًا، يعمل Omega-Fire في مجلده الخاص:

```text
var/exports/       # مجلد داخلي في المشروع
/var/exports/      # مسار مطلق في النظام
```

لذا فإن `/` في البداية ذات دلالة. ويجب أن يطلب المستخدم صراحةً عمليات الاستيراد والتصدير نحو النظام.

## الخوادم الخلفية والتوافق

يكتشف Omega-Fire المكونات ولا يفعّل إلا الوظائف القابلة للاستخدام.

| المكوّن | الدور | الحالة |
|---|---|---|
| nftables | جدار ناري حديث IPv4/IPv6 | موصى به |
| iptables | جدار ناري IPv4 | متوافق |
| ip6tables | جدار ناري IPv6 مع iptables | متوافق إن توفر |
| Fail2Ban | jails وحظر مؤتمت | اختياري |
| conntrack | الاتصالات النشطة | اختياري |
| lnav | تحليل متقدم للسجلات | اختياري |
| systemd، runit، OpenRC | إدارة الخدمات | اكتشاف تلقائي |
| Docker، VNC، الخوادم | التطبيقات والخدمات المكتشفة | حسب التثبيت |

### IPv4 وIPv6

تدعم الخوادم الخلفية المتوافقة عائلتي العناوين كلتيهما:

- nftables: IPv4 وIPv6 بنمط dual stack؛
- iptables/ip6tables: حسب الملفات التنفيذية المتاحة؛
- Fail2Ban: حسب تهيئة الـ jail والنظام.

تعالج المكونات المعنية صيغ IPv6 الطويلة والمضغوطة والمحلية والمختلطة وذات الأصفار وبترميز CIDR.

## الاستمرارية والسجلات والتصدير

### الاستمرارية

- SQLite عبر `sqlite3`.
- جداول خاصة بالحظر والقواعد والتدقيقات واللقطات.
- عمليات ترحيل ذات إصدارات تُطبَّق تلقائيًا.
- أرشيفات للحالة الكاملة بصيغة `.tar.gz`.
- التثبيتات (مصادر السجلات المفضلة) والسجل الحديث محفوظة بصيغة JSON (`var/runtime/`)، وتبقى بعد إعادة التشغيل.

### السجلات

- سجل نصي للتطبيق: `var/logs/app.log`.
- سجل تدقيق JSON منظَّم يتضمن خصوصًا `event_type` و`actor` و`action` و`result` و`details`.

### التصدير

التصدير متاح بصيغ JSON وTXT وHTML، مع عدة سمات CSS لتقارير HTML.

## الأمان

يعمل Omega-Fire على مكونات حرجة في النظام ويجب استخدامه بحذر.

- يتطلب التشغيل صلاحيات root عبر `sudo`.
- قد يكون التفريغ والتنظيف العام وتطبيق سياسة إجراءات مدمّرة.
- تطلق السياسة المعرّفة مسبقًا نسخًا احتياطيًا تلقائيًا قبل التعديل.
- على iptables / ip6tables، يؤدي تطبيق سياسة أو تفريغ واجهة خلفية إلى محو قواعد الأدوات الأخرى أيضًا (UFW…): ينبّه Omega-Fire إلى ذلك ويترك لك الاختيار قبل التنفيذ.
- أجرِ نسخًا احتياطيًا يدويًا قبل كل تغيير كبير.
- تحقق من الحالة الفعلية للجدار الناري والـ jails والاتصالات بعد كل عملية.
- اختبر أولًا على جهاز أو هدف قابل للاستغناء عنه.
- استخدم شبكات التوثيق في RFC 5737 لتجارب IPv4: `192.0.2.0/24` و`198.51.100.0/24` و`203.0.113.0/24`.
- تحقق من التصديرات واللقطات قبل استعادتها على جهاز إنتاج.
- لا تمنح المجلد `var/` أذونات أوسع من اللازم.

## الاختبارات والجودة

تضم المجموعة 137 اختبار وحدة (أكثر من 8000 حالة مُتحقَّق منها): مجال العمل، والتنسيق (`application/`)، والبنية التحتية، وشاشات Textual المضافة أو المصحّحة في 3.5، تُشغَّل بأوراق الأنماط الحقيقية (التخطيط، والمسارات الكاملة، ولغات التصدير). لا يحتوي هذا الأرشيف على المجلد `tests/`: احصل عليه من مستودع التطوير إن احتجت إلى تشغيله.

```bash
source .venv/bin/activate
python -m unittest discover -s tests/unit -t .
```

تفصل البنية متعددة الطبقات مجال العمل عن العرض فصلًا صارمًا (`domain/`، و`application/`، و`ports/` على شكل `Protocol`، انظر [البنية](#البنية)): لا تحتاج معظم الاختبارات إلى root ولا إلى جدار ناري حقيقي.

إذا كنت تساهم في المشروع، فثبّت أدوات الجودة المعلنة (كتعليق) في `requirements.txt`:

```bash
pip install pytest pytest-cov black flake8 mypy
```

الأدوات المتاحة بعد تثبيتها:

```bash
black .
flake8 .
mypy src/
pytest --cov
```

## حالة المشروع

### النقاط العاملة

- TUI موحّدة مبنية على Textual لآليات أمان الشبكة الرئيسية، ونماذج متحقَّق منها، وسمات ومساعدة سياقية مشتركة مع مجموعة OMEGA.
- واجهة Rich التاريخية محتفَظ بها كبديل (`--legacy-cli`).
- اكتشاف تلقائي للقدرات.
- إدارة الخوادم الخلفية المتاحة.
- دعم IPv4/IPv6 حسب الأدوات الموجودة.
- تسجيل التطبيق والتدقيق.
- النسخ الاحتياطي والاستعادة.
- تصدير JSON وTXT وHTML.
- لوحة معلومات وإحصاءات تُحدَّث في الخلفية دون حجب الواجهة.
- بنية طبقية موثّقة.

### القيود المعروفة

- تغطي مجموعة الاختبارات شاشات Textual في 3.5، وليس بعد كل الشاشات الأقدم (انظر [الاختبارات والجودة](#الاختبارات-والجودة)).
- ما زالت آلية `ExecutionPlan`/`PipelineStep` موجودة جزئيًا في المشروع.
- يعتمد التوفر الدقيق للوظائف على الملفات التنفيذية والخدمات والأذونات وتهيئات الجهاز المضيف.
- لم تعد واجهة Rich التاريخية (`--legacy-cli`) محور التطوير النشط؛ وهي محتفَظ بها ريثما تصبح واجهة Textual موثوقة تمامًا في الظروف الفعلية.

## إلغاء التثبيت

إذا بقيت البيانات في مجلد المشروع:

```bash
sudo rm -rf ~/omega-fire
```

احذف يدويًا الملفات المصدَّرة إلى أماكن أخرى، والأسماء المستعارة `fire` المضافة في `~/.bashrc` أو `~/.zshrc` إن وُجدت، وكذلك المجموعة المخصصة إن لم تعد مستخدمة:

```bash
sudo groupdel omega-fire
```

لا تنفّذ هذا الأمر الأخير إلا إذا لم يكن أي ملف أو خدمة أخرى يعتمد على هذه المجموعة.
